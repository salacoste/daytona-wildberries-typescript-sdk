Инструкции по рецензированию переводов / Translation Review Instructions ​

Руководство для носителей русского языка по проверке качества переводов документации.

Guide for native Russian speakers to review translation quality.

Обзор / Overview ​

Эта документация была переведена с использованием AI-ассистированного перевода (гибридный подход). Необходима проверка носителем русского языка для обеспечения:

  • Точности технических терминов
  • Естественности русского языка
  • Согласованности терминологии
  • Корректности культурного контекста

This documentation was translated using AI-assisted translation (hybrid approach). Native speaker review is required to ensure:

  • Technical term accuracy
  • Natural Russian language flow
  • Terminology consistency
  • Cultural context correctness

Контрольный список проверки / Review Checklist ​

A. Техническая точность / Technical Accuracy ​

✅ Проверьте:

  1. Технические термины

    • Согласованы ли переводы терминов по всем документам?
    • Используются ли корректные русские эквиваленты?
    • Сохранены ли английские термины там, где это необходимо (SDK, API, TypeScript)?

  2. Примеры кода

    • Работают ли примеры кода без изменений?
    • Корректны ли русские комментарии в коде?
    • Понятны ли объяснения для русскоязычных разработчиков?

  3. Wildberries специфичные термины

    • Используются ли официальные термины Wildberries?
    • Корректно ли описаны процессы FBS/FBW?
    • Точны ли описания статусов заказов, категорий, характеристик?

B. Качество языка / Language Quality ​

✅ Проверьте:

  1. Грамматика и орфография

    • Нет ли грамматических ошибок?
    • Правильно ли используются падежи?
    • Соблюдены ли правила пунктуации?

  2. Стиль и тон

    • Соответствует ли тон техническому документу?
    • Понятен ли текст для целевой аудитории (разработчиков)?
    • Избегаются ли буквальные переводы английских идиом?

  3. Естественность языка

    • Звучит ли текст естественно для носителя русского языка?
    • Нет ли кальки с английского?
    • Используются ли привычные для русскоязычных разработчиков обороты?

C. Согласованность / Consistency ​

✅ Проверьте:

  1. Терминология

    • Одинаковы ли переводы одних и тех же терминов в разных документах?
    • Соответствуют ли переводы глоссарию TRANSLATION_GLOSSARY.md?
    • Нет ли синонимов там, где должен быть один термин?

  2. Форматирование

    • Сохранено ли форматирование Markdown?
    • Корректны ли ссылки между документами?
    • Работают ли якорные ссылки (anchors)?

  3. Структура

    • Соответствует ли структура перевода оригиналу?
    • Сохранены ли все разделы?
    • Корректны ли заголовки и подзаголовки?

Процесс рецензирования / Review Process ​

Шаг 1: Подготовка / Preparation ​

  1. Прочитайте TRANSLATION_GLOSSARY.md для понимания принятых переводов
  2. Ознакомьтесь с оригинальными английскими документами для контекста
  3. Подготовьте инструменты для проверки (текстовый редактор, браузер для предпросмотра Markdown)

Шаг 2: Первичная проверка / Initial Review ​

  1. Прочитайте документ полностью для общего понимания
  2. Отметьте места, которые вызывают вопросы или звучат неестественно
  3. Проверьте примеры кода на работоспособность

Шаг 3: Детальная проверка / Detailed Review ​

  1. Проверьте каждый раздел по контрольному списку выше
  2. Сверьте технические термины с глоссарием
  3. Убедитесь в согласованности терминологии между документами

Шаг 4: Предложения по улучшению / Improvement Suggestions ​

  1. Запишите все найденные проблемы
  2. Предложите исправления или альтернативные формулировки
  3. Укажите уровень критичности (критичная ошибка / рекомендация)

Типичные проблемы для проверки / Common Issues to Check ​

1. Калька с английского / English Calques ​

❌ Неправильно:

  • "Пожалуйста заметьте" (Please note)
  • "Это позволяет вам к..." (This allows you to...)
  • "Вы будете способны к..." (You will be able to...)

✅ Правильно:

  • "Обратите внимание"
  • "Это позволяет..."
  • "Вы сможете..."

2. Технические термины / Technical Terms ​

❌ Неправильно:

  • Переводить "callback" как "перезвон"
  • Переводить "SDK" как "набор средств разработки"
  • Переводить "TypeScript" как "ТайпСкрипт"

✅ Правильно:

  • Оставить "callback" или использовать "обратный вызов"
  • Оставить "SDK" как есть
  • Оставить "TypeScript" как есть

3. Контекстные переводы / Contextual Translations ​

Пример: Слово "upload"

  • В контексте файлов: "загрузить (на сервер)" / "загрузка"
  • Может требовать уточнения направления

4. Согласование / Agreement ​

Проверьте согласование:

  • Числительных с существительными ("1 товар", "2 товара", "5 товаров")
  • Прилагательных с существительными
  • Глаголов с подлежащими

Критерии качества / Quality Criteria ​

Перевод считается готовым, когда:

✅ Технические требования:

  • [ ] Все технические термины точны и согласованы
  • [ ] Примеры кода работают корректно
  • [ ] Ссылки между документами функционируют
  • [ ] Форматирование Markdown сохранено

✅ Языковые требования:

  • [ ] Текст естественен для носителя русского языка
  • [ ] Нет грамматических или орфографических ошибок
  • [ ] Стиль соответствует техническому документу
  • [ ] Терминология согласована по всем документам

✅ Функциональные требования:

  • [ ] Документ выполняет ту же функцию, что и оригинал
  • [ ] Русскоязычный разработчик может следовать инструкциям
  • [ ] Все шаги понятны и выполнимы
  • [ ] Примеры вывода корректны для русской локали
