**Date:** 2026-08-09
**SDK Version:** 4.1.0
**Status:** Mature, production-ready documentation set (bilingual EN/RU)

## Overview

The Wildberries TypeScript SDK ships with a complete, bilingual (EN/RU)
documentation set: a **VitePress** website (guides, module pages, examples,
migration paths) plus a generated **TypeDoc** API reference. The earlier
"Phase 1 Foundation Complete / awaiting approval" framing reflected a past
planning milestone; the work it described has long since been delivered and
extended. This document is a concise summary of what exists today.

The SDK itself is at **v4.1.0**, with **14 public modules**, ~**2,376 tests
across 80 test files**, and **223 Backlog.md tasks — all Done**. Work tracking
has moved from the legacy Epic/Story system to **Backlog.md**
(`backlog/tasks/`).

## Migration Guides (kept current with WB API changes)

The SDK follows Wildberries endpoint deprecations and ships migration guides
alongside each breaking change:

- `docs/guides/migration-v4.md` — v4.0.0 major (removal of WB-dead surface)
- `docs/guides/migration-v2.7-analytics-v3.md` — Analytics v3 sales-funnel
- `docs/guides/migration-v2.4-promotion-deprecation.md`
- `docs/guides/migration-type8-to-type9.md`
- `docs/guides/migration-item-rating-v2.md` — `getItemRating()` →
  `getItemRatingV2()` (v4.1.0 deprecation, WB deadline 2026-07-30)

(Old version numbers inside a migration guide's title are intentional — they
document a specific upgrade path and are not "stale".)

## How the Docs Are Built

```bash
npm run docs:api      # TypeDoc API reference
npm run docs:dev      # VitePress dev server (live preview)
npm run docs:build    # TypeDoc + VitePress production build
npm run validate:links    # check internal doc links
npm run validate:examples # type-check doc examples
```

The site is published to GitHub Pages at
`salacoste.github.io/daytona-wildberries-typescript-sdk`.

## Known Gap

module was added after the module-page set was written. This is the single
notable documentation gap; closing it is a candidate for a future Backlog.md
task, not a blocker.
