## Руководство по переводу / Translation Guidelines

### 1. Технические термины
- Многие технические термины оставляем как есть: SDK, API, HTTP, JSON, TypeScript, npm, Node.js
- В коде всегда используем английские термины для совместимости

### 2. Комментарии в коде
- Переводим комментарии на русский для лучшего понимания
- Названия переменных, функций, классов оставляем на английском

### 3. Согласованность
- Всегда используем одни и те же переводы для одних и тех же терминов
- Проверяем этот глоссарий перед переводом новых документов

### 4. Контекст
- Учитываем контекст при переводе (например, "upload" может быть "загрузить" в разных контекстах)
- Сохраняем технический смысл, даже если перевод звучит менее естественно

### 5. Примеры вывода
- В примерах вывода консоли используем русский язык для сообщений
- Но сохраняем структуру данных и имена полей на английском

## Для рецензентов / For Reviewers

При проверке переводов обратите внимание на:

**✅ Проверьте:**
- Согласованность терминологии с этим глоссарием
- Точность технических переводов
- Естественность русского языка
- Сохранение технического смысла
- Корректность примеров кода с русскими комментариями

**❌ Избегайте:**
- Буквального перевода английских идиом
- Изменения технических терминов в коде
- Несогласованных переводов одних и тех же терминов
- Потери технической точности ради "красивого" языка
