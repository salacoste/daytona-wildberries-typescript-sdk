# Миграция фильтра `withPhoto`

**Аудитория**: Разработчики, вызывающие `sdk.products.getCardsList()` с `withPhoto: 0` или полагающиеся на поведение по умолчанию (без фильтра).
**Начиная с**: SDK v3.14.0
**Жёсткий дедлайн**: 2026-06-16

---

## Почему это важно

15 мая 2026 г. Wildberries объявил о **скрытом изменении семантики** фильтра `withPhoto` в методе `POST /content/v2/get/cards/list`. Изменение вступает в силу **2026-06-16**.

Это наиболее опасный тип изменения API: то же поле, тот же тип, то же числовое значение `0` — **другой набор результатов**. WB по-прежнему будет возвращать HTTP 200 с корректными карточками — никакой ошибки, никакого сигнала об изменении.

**Влияние на бизнес**: Код, который сейчас использует `withPhoto: 0` для поиска «карточек без фото» и их исправления, после 2026-06-16 незаметно начнёт включать в выборку карточки **с фотографиями**. Операции с данными (загрузка фото, аудит качества, массовое редактирование) затронут неправильные карточки.

---

## Что меняется

| Значение | Сейчас (до 2026-06-16) | После (с 2026-06-16) | Изменение |
|----------|------------------------|----------------------|-----------|
| `-1` | Все карточки | Все карточки | Без изменений |
| `0` или отсутствие | Только карточки **без** фото | Все карточки (с фото и без) | **Скрытое изменение семантики** |
| `1` | Только карточки **с** фото | Только карточки **с** фото | Без изменений |
| `2` | Не существует | Только карточки **без** фото | Новое значение |

Константа `WITH_PHOTO_FILTER` (добавлена в v3.14.0) использует **постмиграционную** семантику: `WITH_PHOTO_FILTER.NO_PHOTO` равно `2`.

---

## Матрица миграции

| Текущий код | Намерение | Требуемые действия |
|-------------|-----------|-------------------|
| `getCardsList({})` | «Все карточки» | Изменений не требуется — поведение улучшится после дедлайна (ранее случайно возвращало «только без фото») |
| `getCardsList({})` | «Только карточки без фото» | Необходимо добавить `filter: { withPhoto: 2 }` до 2026-06-16 |
| `getCardsList({ settings: { filter: { withPhoto: 0 } } })` | «Только карточки без фото» | Необходимо изменить на `withPhoto: 2` до 2026-06-16 |
| `getCardsList({ settings: { filter: { withPhoto: 1 } } })` | «Только карточки с фото» | Изменений не требуется |
| `getCardsList({ settings: { filter: { withPhoto: -1 } } })` | «Все карточки» | Изменений не требуется |

## Примеры кода

### Сценарий 1 — Исправление карточек без фото (наиболее распространённый случай)

```typescript
// ДО (работает сейчас, молча сломается после 2026-06-16):
const result = await sdk.products.getCardsList({
  settings: {
    cursor: { limit: 100 },
    filter: { withPhoto: 0 },
  },
});
// После дедлайна: result.cards будет содержать ВСЕ карточки, а не только без фото

// ПОСЛЕ (корректно, работает и до, и после 2026-06-16):
import { WITH_PHOTO_FILTER } from 'daytona-wildberries-typescript-sdk';

const result = await sdk.products.getCardsList({
  settings: {
    cursor: { limit: 100 },
    filter: { withPhoto: WITH_PHOTO_FILTER.NO_PHOTO }, // = 2
  },
});
// result.cards содержит только карточки без фото
```

### Сценарий 2 — Получение всех карточек (без явного фильтра)

```typescript
// ДО (сейчас возвращает только без фото — вероятно, ненамеренно):
const result = await sdk.products.getCardsList({
  settings: { cursor: { limit: 100 } },
});

// ПОСЛЕ (тот же код, поведение улучшается после 2026-06-16 — возвращает все карточки):
// Изменений не требуется, если намерение — «все карточки».
// Для наглядности можно добавить явный фильтр:
import { WITH_PHOTO_FILTER } from 'daytona-wildberries-typescript-sdk';

const result = await sdk.products.getCardsList({
  settings: {
    cursor: { limit: 100 },
    filter: { withPhoto: WITH_PHOTO_FILTER.ALL }, // = -1, явно
  },
});
```

### Сценарий 3 — Явный запрос всех карточек (уже корректно)

```typescript
// ДО и ПОСЛЕ — изменений не требуется:
const result = await sdk.products.getCardsList({
  settings: {
    cursor: { limit: 100 },
    filter: { withPhoto: -1 },
  },
});
```

## Вспомогательная константа `WITH_PHOTO_FILTER`

SDK v3.14.0 поставляется с именованной константой для самодокументируемого и безопасного кода:

```typescript
import { WITH_PHOTO_FILTER } from 'daytona-wildberries-typescript-sdk';

// Доступные значения:
WITH_PHOTO_FILTER.ALL        // -1 — все карточки (не меняется до/после дедлайна)
WITH_PHOTO_FILTER.WITH_PHOTO //  1 — только с фото (не меняется)
WITH_PHOTO_FILTER.NO_PHOTO   //  2 — только без фото (НОВОЕ постмиграционное значение)
```

Использование `WITH_PHOTO_FILTER.NO_PHOTO` вместо числа `2` даёт следующие преимущества:
- Намерение очевидно при ревью кода и в диффах.
- Если WB снова изменит значение, обновление константы — изменение в одной строке.
- IDE показывает JSDoc с информацией о дедлайне при наведении курсора.

## Часто задаваемые вопросы

**В: SDK автоматически конвертирует `withPhoto: 0` в `2`?**
О: Нет. Автоконверсия изменяла бы намерение потребителя без его согласия. SDK выдаёт одноразовое предупреждение `console.warn` при первом вызове с `withPhoto: 0`, затем передаёт значение без изменений. Обновление кода — ваша ответственность.

**В: Как выглядит сообщение `console.warn`?**
О: Первый вызов в процессе с `withPhoto: 0` выводит:
```
products.getCardsList: `withPhoto: 0` will change semantics on 2026-06-16. Today it means
"only cards without photo"; after the deadline it will mean "ALL cards" (any photo state).
If you want "no photo only", migrate to `WITH_PHOTO_FILTER.NO_PHOTO` (= 2). If you want
"all cards", use `WITH_PHOTO_FILTER.ALL` (= -1) for clarity.
See docs/guides/withphoto-semantic-migration.md.
```
Предупреждение срабатывает один раз за время жизни процесса (последующие вызовы с `withPhoto: 0` не выводят предупреждение).

**В: Если фильтр не указан — будет ли предупреждение?**
О: Нет. Вызов без фильтра — наиболее распространённый сценарий («дай все мои карточки»). Предупреждение для каждого такого вызова добавляло бы лишний шум для большинства потребителей, у которых нет необходимости в миграции. CHANGELOG и данное руководство явно охватывают этот сценарий.

**В: Можно ли передавать `withPhoto: 2` уже сейчас, до развёртывания изменения WB?**
О: Это зависит от того, развернул ли WB уже поддержку `withPhoto: 2` в своём API. Примечания к релизу SDK v3.14.0 включают замечание о проверке в песочнице. Если песочница WB возвращает ошибку для `withPhoto: 2`, отложите развёртывание до подтверждения WB о готовности нового значения.

**В: Тип `withPhoto?: number` будет сужен до литерального объединения?**
О: Нет. Тип остаётся `withPhoto?: number`, чтобы не нарушать работу потребителей, передающих значения из конфигурационных файлов, переменных окружения или нетипизированного JavaScript. `WITH_PHOTO_FILTER` предоставляет типобезопасность по желанию, не навязывая её всем.
