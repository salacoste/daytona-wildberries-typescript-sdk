1. `uploadMedia(productId: string, files: MediaFile[])` method uploads product images
2. `getMediaList(productId: string)` method retrieves all media for a product
3. `deleteMedia(productId: string, mediaId: string)` method removes specific media
4. `updatePricing(data: PricingUpdate[])` method updates prices for multiple products
5. `getPricing(productIds: string[])` method retrieves current pricing
6. Media upload supports proper content-type headers and file size validation
7. Pricing updates support bulk operations with proper error handling per product
8. Rate limits enforced for media operations (typically stricter than other operations)
9. Unit tests validate media and pricing method contracts
10. Integration tests with MSW validate file upload simulation and bulk pricing updates
11. Example code demonstrates complete product setup with images and pricing

### API Specifications

**Media Base URL**: `https://content-api.wildberries.ru`
**Pricing Base URL**: `https://discounts-prices-api.wildberries.ru`
[Source: OpenAPI spec wildberries_api_doc/02-products.yaml]

**Media Endpoints**:

1. **POST /content/v3/media/file** - Upload Single Media File
   - **Method**: multipart/form-data upload
   - **Headers**:
     - `X-Nm-Id`: Wildberries article ID (required)
     - `X-Photo-Number`: Photo number 1-30, video always 1 (required)
     - `Content-Type`: multipart/form-data
   - **Body**: Form data with `uploadfile` field (Buffer/Blob)
   - **Response**: `{ data: {}, error: boolean, errorText: string }`
   - **Rate limit**: 100 req/min, 600ms interval, 5 burst
   - **Photo Number Rules**:
     - Starts at 1
     - For video, always use 1
     - To add to existing photos, use number > current count
   [Source: Line 3228-3320 in 02-products.yaml]

2. **POST /content/v3/media/save** - Upload Media via URLs
   - **Request body**: `{ nmId: number, data: string[] }` (URLs array)
   - **CRITICAL**: New media COMPLETELY REPLACES old media
   - **To Add**: Include both new AND old URLs in request
   - **Response**: `{ data: {}, error: boolean, errorText: string }`
   - **All-or-Nothing**: If ANY file fails validation, NONE upload
   - **Rate limit**: 100 req/min, 600ms interval, 5 burst
   - **URL Requirements**:
     - Direct file link (not preview/HTML page)
     - No authentication required
     - Must return file content, not text
   [Source: Line 3319-3400 in 02-products.yaml]

**Media Requirements**:
- **Images**: Max 30, min 700×900px, max 32MB, min 65% quality, formats: JPG/PNG/BMP/GIF(static)/WebP
- **Video**: Max 1, max 50MB, formats: MOV/MP4
[Source: Line 3235-3248 in 02-products.yaml]

**Pricing Endpoints**:

1. **POST /api/v2/upload/task** - Set Prices and Discounts
   - **Request body**: `{ data: PricingUpdate[] }`
   - **PricingUpdate**: `{ nmID: number, price?: number, discount?: number }`
   - **Async Processing**: Returns `{ uploadID: string }` - poll status endpoint
   - **Response 200 OK**: Means task queued, NOT that prices updated
   - **Validation**: Prices must be integers, discounts 0-99%
   - **Rate limit**: 10 req per 6 seconds, 600ms interval, 5 burst
   [Source: Line 3400-3484 in 02-products.yaml]

2. **GET /api/v2/list/goods/filter** - Get Pricing (Single Product)
   - **Query params**: `filterNmID: number` (single nmID only)
   - **Pagination**: `limit` (max 1000), `offset` for all products
   - **Returns**: `{ data: PricingInfo[] }` - prices, discounts, currency, WB Club discounts
   - **Rate limit**: 10 req per 6 seconds
   [Source: Line 3843-3920 in 02-products.yaml]

3. **POST /api/v2/list/goods/filter** - Get Pricing (Multiple Products)
   - **Request body**: `{ nmIDs: number[] }` (multiple nmIDs)
   - **Returns**: `{ data: PricingInfo[] }`
   - **Rate limit**: 10 req per 6 seconds
   [Source: Line 3920+ in 02-products.yaml]

4. **GET /api/v2/history/tasks** - Get Pricing Task Status
   - **Query params**: `uploadID: string` (from updatePricing response)
   - **Returns**: Task status (pending, processing, completed, failed)
   - **Use**: Poll after updatePricing() to verify prices applied
   - **Rate limit**: 10 req per 6 seconds
   [Source: Line 3640-3690 in 02-products.yaml]

**Authentication**: Bearer token via `Authorization` header (handled by BaseClient)
[Source: OpenAPI spec - security scheme HeaderApiKey]

### Critical Implementation Notes

**1. Media Upload Replaces All Existing Media** ⚠️

`uploadMediaByURLs()` COMPLETELY REPLACES all existing media. To add new media, you MUST include both new and old URLs.

**Example**:
```typescript
// BAD - Loses existing media
await sdk.products.uploadMediaByURLs(nmID, ['https://new-photo.jpg']);

// GOOD - Preserves existing media
const existing = await sdk.products.getMediaList(nmID);
await sdk.products.uploadMediaByURLs(nmID, [...existing, 'https://new-photo.jpg']);
```

[Source: Line 3324 in 02-products.yaml - Method description]

**2. No Dedicated Media Delete Endpoint**

Wildberries API doesn't provide an endpoint to delete individual media files. To "delete" media, use `uploadMediaByURLs()` with only the URLs you want to keep. Omitted URLs are effectively deleted.

**3. All-or-Nothing Media Upload**

When uploading via URLs, if ANY file fails validation (size, format, dimensions), NONE of the files upload - even if some are valid.

[Source: Line 3352 in 02-products.yaml - Validation note]

**4. Async Pricing Updates**

`updatePricing()` returns immediately with a task ID. Prices are NOT updated yet. You must poll `getPricingTaskStatus()` to verify when pricing is applied.

**Workflow**:
```typescript
// 1. Submit pricing update
const task = await sdk.products.updatePricing([...]);

// 2. Poll task status
let status;
do {
  await new Promise(resolve => setTimeout(resolve, 1000));
  status = await sdk.products.getPricingTaskStatus(task.uploadID);
} while (status.status === 'processing');

// 3. Verify pricing applied
if (status.status === 'completed') {
  const pricing = await sdk.products.getPricing(nmID);
}
```

[Source: Line 3408 in 02-products.yaml - Async processing note]

**5. Prices Must Be Integers**

The pricing API only accepts whole number prices. Decimal prices will cause validation errors.

```typescript
// BAD
await updatePricing([{ nmID: 123, price: 29.99 }]); // ERROR

// GOOD
await updatePricing([{ nmID: 123, price: 2999 }]); // OK (store in kopecks or round)
```

[Source: Pricing API validation examples in 02-products.yaml]

**6. Different Base URLs for Media vs Pricing**

Media endpoints use `content-api.wildberries.ru`, while pricing endpoints use `discounts-prices-api.wildberries.ru`. Ensure correct base URLs in method implementations.

### Rate Limiting Configuration

**Media Endpoints** (Content API limits):
- 100 requests per minute
- 600 millisecond interval
- Burst limit: 5 requests
- **Affects**: uploadMediaFile, uploadMediaByURLs

**Pricing Endpoints** (Pricing API limits - STRICTER):
- 10 requests per 6 seconds (equivalent to 100 req/min but enforced differently)
- 600 millisecond interval
- Burst limit: 5 requests
- **Affects**: updatePricing, getPricing, getPricingTaskStatus

**Implementation**:
- BaseClient's RateLimiter enforces limits via rateLimitKey
- Different keys allow independent rate limiting per endpoint
- Pricing API limits are stricter - handle carefully in bulk operations
