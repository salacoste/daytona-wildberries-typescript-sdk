## Context

### Background

The Analytics module is a HIGH priority business intelligence module enabling sellers to access comprehensive performance data across multiple dimensions. This includes sales funnel analysis (conversion from views to purchases), search query performance (how customers find products), stock level history, and CSV export capabilities for offline analysis. Analytics data is critical for optimizing product listings, pricing strategies, and inventory management.

**Key Analytics Operations**:
- **Sales Funnel Analytics**: Track conversion metrics (views → add to cart → orders → buyouts) with period-over-period comparison
- **Search Query Analytics**: Understand how customers search for and find your products
- **Stock History Analytics**: Monitor inventory levels over time across products and warehouses
- **CSV Export System**: Download comprehensive analytics data for offline analysis and reporting

### Technical Context

> **v2.7.0 Migration Note (EPIC 13)**: The v2 Sales Funnel endpoints listed below (`/api/v2/nm-report/detail`, `/detail/history`, `/grouped/history`) have been replaced by v3 endpoints (`/api/analytics/v3/sales-funnel/products`, `/products/history`, `/grouped/history`). The SDK v2.7.0 adds new v3 methods (`getSalesFunnelProducts()`, `getSalesFunnelProductsHistory()`, `getSalesFunnelGroupedHistory()`) and deprecates the old v2 wrappers (`createNmReportDetail()`, `createDetailHistory()`, `createGroupedHistory()`). See `docs/guides/migration-v2.7-analytics-v3.md` for details.

  private validateDateRange(begin: string, end: string): void {
    const beginDate = new Date(begin);
    const endDate = new Date(end);
    const daysDiff = Math.floor((endDate.getTime() - beginDate.getTime()) / (1000 * 60 * 60 * 24));

    if (daysDiff > 365) {
      throw new ValidationError('Date range cannot exceed 365 days');
    }

    if (beginDate > endDate) {
      throw new ValidationError('Begin date must be before end date');
    }
  }

### Date Range Validation

**Business Rules**:
- Maximum range: 365 days
- Begin date must be before end date
- Previous period auto-calculated (same duration)
- If previous period >365 days ago, adjusted to 365 days from current date

**Validation Implementation**:
```typescript
private validateDateRange(begin: string, end: string): void {
  const beginDate = new Date(begin);
  const endDate = new Date(end);
  const daysDiff = Math.floor((endDate.getTime() - beginDate.getTime()) / (1000 * 60 * 60 * 24));

  if (daysDiff > 365) {
    throw new InvalidDateRangeError('Date range cannot exceed 365 days');
  }

  if (beginDate > endDate) {
    throw new InvalidDateRangeError('Begin date must be before end date');
  }
}
```

### CSV Download Workflow

**Lifecycle**:
1. **Request**: POST to /downloads with period and filters
2. **Poll**: GET /downloads to check status
3. **Download**: GET /downloads/file/{id} when status = COMPLETED
4. **Retry**: POST /downloads/retry if status = FAILED

**Status States**:
- PENDING: Request received, queued
- PROCESSING: CSV being generated
- COMPLETED: Ready for download
- FAILED: Generation error (use retry endpoint)
