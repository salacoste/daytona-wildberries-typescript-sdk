# Story 2.6: Orders FBS Module - Shipping and Supply Management

---

## Status

**Done**

---

## Story

**As a** marketplace seller using FBS (Fulfillment by Seller),
**I want** to manage supplies, generate shipping labels, and handle order logistics,
**so that** I can efficiently fulfill orders from my warehouse to WB offices.

---

## Acceptance Criteria

1. `createSupply(name: string)` method creates new supply for grouping orders
2. `getSupplies(filters?: SupplyFilters)` method retrieves supplies with pagination
3. `getSupply(supplyId: string)` method retrieves single supply details
4. `addOrderToSupply(supplyId: string, orderId: number)` method adds order to supply (changes status to "confirm")
5. `deliverSupply(supplyId: string)` method marks supply as delivered (changes order status to "complete")
6. `deleteSupply(supplyId: string)` method removes empty supply
7. `getOrderStickers(orderIds: number[], options: StickerOptions)` method retrieves shipping labels (base64-encoded)
8. `getSupplyBarcode(supplyId: string, type: BarcodeType)` method retrieves supply QR code
9. `cancelOrder(orderId: number)` method cancels order (changes status to "cancel")
10. Sticker types support SVG, PNG, ZPLV, ZPLH formats with size options
11. Supply workflow: create → add orders → get stickers → deliver → get barcode
12. Cargo type constraints enforced (supply can only contain orders of same cargoType)
13. Rate limits enforced per endpoint
14. Unit tests validate all supply and shipping methods
15. Integration tests validate complete shipping workflow with MSW
16. Example code demonstrates end-to-end FBS fulfillment (create supply → add orders → labels → deliver)

    ```typescript
    import { WildberriesSDK } from '../src';
    import { writeFileSync } from 'fs';

    const sdk = new WildberriesSDK({ apiKey: process.env.WB_API_KEY! });

    async function completeFBSFulfillment() {
      console.log('=== Complete FBS Order Fulfillment Workflow ===\n');

      // Step 1: Get new orders
      console.log('Step 1: Fetching new orders...');
      const newOrders = await sdk.ordersFBS.getNewOrders();
      console.log(`Found ${newOrders.length} new orders\n`);

      if (newOrders.length === 0) {
        console.log('No new orders to process');
        return;
      }

      // Step 2: Create supply
      console.log('Step 2: Creating supply...');
      const supplyName = `Supply ${new Date().toISOString().split('T')[0]}`;
      const supply = await sdk.ordersFBS.createSupply(supplyName);
      console.log(`Supply created: ${supply.id}\n`);

      // Step 3: Add orders to supply (changes status new → confirm)
      console.log('Step 3: Adding orders to supply...');
      for (const order of newOrders.slice(0, 5)) {
        try {
          await sdk.ordersFBS.addOrderToSupply(supply.id, order.id);
          console.log(`  ✅ Added order ${order.id} (article: ${order.article})`);
        } catch (error) {
          console.log(`  ❌ Failed to add order ${order.id}: ${error.message}`);
          // Might fail due to cargoType mismatch
        }
      }

      // Step 4: Verify statuses changed to "confirm"
      console.log('\nStep 4: Verifying order statuses...');
      const orderIds = newOrders.slice(0, 5).map(o => o.id);
      const statuses = await sdk.ordersFBS.getOrderStatuses(orderIds);
      statuses.forEach(status => {
        console.log(`  Order ${status.id}: ${status.supplierStatus}`);
      });

      // Step 5: Generate shipping labels
      console.log('\nStep 5: Generating shipping labels (PNG, 580×400)...');
      const confirmedOrders = statuses
        .filter(s => s.supplierStatus === 'confirm')
        .map(s => s.id);

      if (confirmedOrders.length > 0) {
        const stickers = await sdk.ordersFBS.getOrderStickers(
          confirmedOrders,
          { type: 'png', width: 58, height: 40 }
        );

        console.log(`Generated ${stickers.length} stickers`);

        // Save first sticker to file
        if (stickers.length > 0) {
          const stickerData = Buffer.from(stickers[0].file, 'base64');
          writeFileSync('order-sticker.png', stickerData);
          console.log(`  Saved first sticker to order-sticker.png`);
          console.log(`  Barcode: ${stickers[0].barcode}`);
        }
      }

      // Step 6: Deliver supply (changes status confirm → complete)
      console.log('\nStep 6: Marking supply as delivered...');
      await sdk.ordersFBS.deliverSupply(supply.id);
      console.log(`Supply ${supply.id} delivered\n`);

      // Step 7: Verify final statuses
      console.log('Step 7: Verifying final order statuses...');
      const finalStatuses = await sdk.ordersFBS.getOrderStatuses(orderIds);
      finalStatuses.forEach(status => {
        console.log(`  Order ${status.id}: ${status.supplierStatus}`);
      });

      // Step 8: Get supply QR code
      console.log('\nStep 8: Generating supply QR code...');
      const qrCode = await sdk.ordersFBS.getSupplyBarcode(supply.id, 'png');
      const qrData = Buffer.from(qrCode.file, 'base64');
      writeFileSync('supply-qrcode.png', qrData);
      console.log(`QR code saved to supply-qrcode.png`);
      console.log(`Barcode value: ${qrCode.barcode}\n`);

      // Step 9: List all supplies
      console.log('Step 9: Listing recent supplies...');
      const supplies = await sdk.ordersFBS.getSupplies({ limit: 10, next: 0 });
      console.log(`Total supplies: ${supplies.supplies.length}`);
      supplies.supplies.forEach(s => {
        console.log(`  ${s.id}: ${s.name} (${s.done ? 'Closed' : 'Open'})`);
      });

      console.log('\n✅ Complete FBS fulfillment workflow finished!');
    }

    completeFBSFulfillment()
      .catch(error => {
        console.error('❌ Error:', error.message);
    ```

5. **PATCH /api/v3/supplies/{supplyId}/orders/{orderId}** - Add Order to Supply

     - All orders must be from same warehouse
     - Can move between active supplies or from closed to active (for reshipment)
   - **409 errors**: cargoType mismatch, warehouse mismatch, supply constraints
   - **Rate limit**: 1000 req/min, 60ms interval (**HIGHER** than other endpoints!)

6. **PATCH /api/v3/supplies/{supplyId}/deliver** - Deliver Supply
   - **Effect**: Closes supply, changes ALL order statuses confirm → complete
   - **Requirement**: Supply must have ≥1 order
   - **After delivery**: Cannot add more orders
   - **Auto-behavior**: Supply auto-closes on first acceptance scan if not manually delivered
   - **409 errors**: Zero orders, UINs not filled (for products requiring UIN metadata)
   - **Rate limit**: 300 req/min, 200ms interval
   - **Special**: 409 errors count as 5 requests
   [Source: Lines 1973-2031 in 03-orders-fbs.yaml]

7. **POST /api/v3/orders/stickers** - Get Order Stickers/Labels

   - **Special**: 409 errors count as 5 requests

### Critical Implementation Notes

**1. Supply Workflow - Complete Status Transitions** 🔄

```
1. Create supply (empty, no cargoType)
2. Add first order → supply gets cargoType, order: new → confirm
3. Add more orders (must match cargoType) → orders: new → confirm
4. Get order stickers (orders must be in confirm status)
5. Deliver supply → orders: confirm → complete, supply closed
6. Get supply QR code (only available after delivery)
```

[Source: Lines 1645-1651, 1766, 1983, 2048 in 03-orders-fbs.yaml]

**2. Cargo Type Constraints** 📦

**CRITICAL**: Supply can only contain orders of same cargo type:

- **Empty supply**: No cargoType
- **First order added**: Supply gets cargoType from order
- **Subsequent orders**: MUST match supply's cargoType
- **Cargo types**: 1=МГТ (small), 2=СГТ (oversized), 3=КГТ+ (large)

**Example**:
```typescript
const supply = await sdk.ordersFBS.createSupply('Mixed Cargo Test');
await sdk.ordersFBS.addOrderToSupply(supply.id, orderMGT); // cargoType: 1, OK
await sdk.ordersFBS.addOrderToSupply(supply.id, orderSGT); // cargoType: 2, ERROR 409!
```

[Source: Lines 1651, 1773-1776 in 03-orders-fbs.yaml]

**3. Same Warehouse Constraint** 🏭

Cannot add orders from different warehouses to same supply.

[Source: Lines 1779-1780 in 03-orders-fbs.yaml]

**4. Base64-Encoded Files** 🖼️

Stickers and QR codes returned as base64-encoded strings in `file` field. Must decode to save as actual files.

**Example**:

```typescript
const stickers = await sdk.ordersFBS.getOrderStickers([123], {...});

```

**5. Rate Limit Variations** ⚖️

Different endpoints have different rate limits:

- **Fast**: addOrderToSupply - 1000 req/min, 60ms interval
- **Standard**: Most operations - 300 req/min, 200ms interval
- **Slow**: cancelOrder - 100 req/min, 600ms interval

[Source: Lines 637, 705, 1658, 1787, 1996, 2057 in 03-orders-fbs.yaml]

**6. 409 Errors Count as 5 Requests** 💥

Conflict errors (409) count as **5 requests** toward rate limit instead of 1.

**Common 409 scenarios**:
- cargoType mismatch when adding order
- Warehouse mismatch
- Delivering supply with zero orders
- Getting QR code before delivery
- Deleting supply with orders
- Canceling completed order

**7. Sticker Status Requirement** 🏷️

Can only get stickers for orders in "confirm" status (on assembly). Orders in "new" status will fail.

Only two valid size combinations:
- 580×400 px (width=58, height=40)

Invalid combinations will cause validation error.

[Source: Lines 697-698 in 03-orders-fbs.yaml]

**9. Auto-Cancel Removes from Supply** 🔄

When order is canceled, it's automatically removed from any supply it was in.
