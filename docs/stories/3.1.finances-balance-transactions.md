**Follows Established Pattern** (from Epic 1 & 2):
- Delegate all HTTP operations to BaseClient
- Rate limiting enforced via `rateLimitKey` parameter
- Error handling inherited from BaseClient (401→AuthenticationError, 429→RateLimitError)
- TypeScript strict mode with zero `any` types

**Transaction Type Handling**:
- Use TypeScript enums for transaction types
- Map API string values to type-safe enums
- Support filtering by single or multiple transaction types

**Date Range Implementation**:
- Accept ISO 8601 date strings
- Provide helper functions for common periods (today, last week, month)
- Handle timezone considerations for date filtering

### Rate Limiting

From OpenAPI spec descriptions, finances endpoints typically have:
- Balance: ~5 requests per minute
- Transactions: ~10 requests per minute with 6-second intervals
- Transaction details: ~20 requests per minute

Extract actual limits from `13-finances.yaml` description fields during code generation.

**Test Framework**: Vitest with TypeScript support

**Coverage Requirements**:
- ≥90% coverage for FinancesModule (critical financial data)
- All public methods must have unit tests
- Integration tests required for complete request/response flows

**Mocking Strategy**:
- Unit tests: Mock BaseClient using Vitest `vi.fn()`
- Integration tests: Use MSW (Mock Service Worker) for HTTP mocking

**Test Patterns**:
```typescript
// Unit test pattern
describe('FinancesModule', () => {
  const mockClient = {
    get: vi.fn(),
  } as unknown as BaseClient;

  const finances = new FinancesModule(mockClient);

  it('should fetch balance', async () => {
    mockClient.get.mockResolvedValue({ available: 1000, pending: 500 });
    const result = await finances.getBalance();
    expect(mockClient.get).toHaveBeenCalledWith(
      'https://finance-api.wildberries.ru/api/v1/balance',
      { rateLimitKey: 'finances.getBalance' }
    );
  });
});

// Integration test pattern with MSW
const server = setupServer(
  http.get('https://finance-api.wildberries.ru/api/v1/balance', () => {
    return HttpResponse.json({ available: 1000, pending: 500 });
  })
);
```

**Test Scenarios to Cover**:
- Happy path: Successful data retrieval
- Error handling: 401 (auth), 429 (rate limit), 500 (server error)
- Validation: Invalid parameters, missing required fields
- Pagination: Large datasets, empty results
- Filtering: Date ranges, transaction types, combinations
