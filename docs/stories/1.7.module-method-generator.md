# Story 1.7: Code Generation Framework - Module Method Generator

---

## Status

**Draft**

---

## Story

**As a** SDK maintainer,
**I want** automated module class generation from OpenAPI paths,
**so that** all API endpoints are implemented with consistent patterns.

---

## Acceptance Criteria

1. Generator parses `paths` from OpenAPI spec and extracts operations (GET, POST, etc.)
2. Generates method name from `operationId` or path pattern (e.g., `/api/v1/ping` → `ping()`)
3. Extracts request parameters and body schema to generate method parameters
4. Maps response schema to TypeScript return type (Promise<ResponseType>)
5. Generates JSDoc with summary, description, parameters, returns, throws, example
6. Includes external documentation links from OpenAPI `externalDocs` field
7. Detects base URL from path-level `servers` configuration
8. Outputs module class to `src/modules/<module>/index.ts`
9. Successfully generates General module from `01-general.yaml` with all endpoints and proper BaseClient delegation

### Architecture Overview

**Module Generation Architecture**

**Component: Module Method Generator**

**Location:** `tools/generators/module-*.ts` files

**Purpose:** Transform OpenAPI `paths` into TypeScript module class with typed methods

**Process Flow:**
```
1. Read OpenAPI YAML file
2. Parse paths section
3. For each path + operation:
   a. Generate method name (from operationId or path)
   b. Extract parameters (query, path, body)
   c. Extract response type
   d. Detect base URL from servers config
   e. Generate JSDoc (summary, params, returns, throws, example, see)
   f. Generate method implementation
4. Generate module class structure
5. Add imports (BaseClient + types)
6. Write to src/modules/{module}/index.ts
7. Format with Prettier
8. Validate with TypeScript compiler
```

**Output Example:**
```typescript

 * Auto-generated module for general
 * Generated from: wildberries_api_doc/01-general.yaml
 * DO NOT EDIT MANUALLY
 */

import type { PingResponse, NewsResponse } from '../../types/general.types';

export class GeneralModule {
  constructor(private client: BaseClient) {}

  /**
   * Проверка подключения
   * @returns Health check response with timestamp
   * @throws {AuthenticationError} When API key is invalid
   * @throws {NetworkError} When network request fails
   * @see {@link https://dev.wildberries.ru/...} - Official docs
   * @example
   * const result = await sdk.general.ping();
   * console.log(result.Status); // 'OK'
   */
  async ping(): Promise<PingResponse> {
    return this.client.get<PingResponse>(
      'https://common-api.wildberries.ru/ping'
    );
  }

  /**
   * Получение новостей портала продавцов
   * @param options Query parameters
   * @param options.from Date from which to get news
   * @param options.fromID News ID from which to start
   * @returns List of news items
   * @throws {AuthenticationError} When API key is invalid
```

### Method Generation Strategy

**Method Naming Priority:**

1. **Use operationId if present** (highest priority)
   - OpenAPI: `operationId: "getSellerInfo"`
   - Generated: `async getSellerInfo()`
   - Already camelCase, use as-is

2. **Generate from path + HTTP method** (fallback)
   - Parse path to extract resource name
   - Combine with HTTP verb
   - Convert to camelCase

**Path Parsing Examples:**

| Path | Method | Generated Name | Logic |
|------|--------|----------------|-------|
| `/ping` | GET | `ping()` | Single segment, use as-is |
| `/api/v1/news` | GET | `getNews()` | Extract resource `news`, prefix with verb |
| `/api/communications/v2/news` | GET | `getNews()` | Extract last meaningful segment |
| `/api/v1/seller/info` | GET | `getSellerInfo()` | Combine `seller` + `info` |
| `/orders/{id}` | GET | `getOrder()` | Singularize resource when path param present |
| `/orders/{id}` | DELETE | `deleteOrder()` | HTTP method becomes verb |
| `/api/v1/balance` | GET | `getBalance()` | Extract `balance`, prefix with GET |

**Path Parsing Algorithm:**
```typescript
function generateMethodNameFromPath(path: string, method: string): string {
  // Remove version segments (/v1, /v2, /api)
  const cleaned = path.replace(/\/(api|v\d+)/g, '');

  // Remove path parameters ({id}, {orderId})
  const withoutParams = cleaned.replace(/\{[^}]+\}/g, '');

  // Split by slashes, filter empty
  const segments = withoutParams.split('/').filter(Boolean);

  // Take last meaningful segments (skip common prefixes)
  const resource = segments.slice(-2).join('');

  // Combine HTTP method + resource
  const verb = methodToVerb(method); // get, post, put, delete
  return toCamelCase(`${verb}_${resource}`);
}
```

**Duplicate Name Handling:**
- Track generated method names in Set
- If duplicate detected, append number: `getNews2()`, `getNews3()`
- Log warning about duplicate

### Parameter Extraction

**Parameter Types:**

1. **Path Parameters** (in URL path)
   - Example: `/orders/{id}` → `id` parameter
   - Always required
   - Extracted from `operation.parameters` where `in === 'path'`
   - Appear first in method signature

2. **Query Parameters** (in URL query string)
   - Example: `?from=2024-01-01&limit=10`
   - Usually optional
   - Extracted from `operation.parameters` where `in === 'query'`
   - Grouped in `options` object parameter

3. **Request Body** (for POST/PUT/PATCH)
   - JSON payload sent in request body
   - Extracted from `operation.requestBody.content['application/json'].schema`
   - Typed as interface (from $ref or inline)
   - Appears last in method signature

**Parameter Signature Patterns:**

```typescript
// No parameters
async ping(): Promise<PingResponse>

// Only query parameters (optional)
async getNews(options?: { from?: string; fromID?: number }): Promise<NewsResponse>

// Path parameter only (required)
async getOrder(id: string): Promise<OrderResponse>

// Path + query parameters
async listOrders(status: string, options?: { limit?: number }): Promise<OrderListResponse>

// Path + body
async updateOrder(id: string, data: UpdateOrderRequest): Promise<OrderResponse>

// Path + query + body
async createProduct(categoryId: string, options?: { validate?: boolean }, data: ProductRequest): Promise<ProductResponse>
```

**Query Parameter Grouping:**
- All query params grouped into single `options` object
- Prevents method signature bloat
- Allows partial parameter passing
- Example: `getNews({ from: '2024-01-01' })` (omit fromID)

### Response Type Extraction

**Response Priority Order:**
1. HTTP 200 (OK) - most common success response
2. HTTP 201 (Created) - for resource creation
3. HTTP 204 (No Content) - maps to `Promise<void>`
4. First 2xx response found
5. `unknown` if no success response

**Schema Resolution:**

```typescript
// $ref reference (most common)
responses:
  '200':
    content:
      application/json:
        schema:
          $ref: '#/components/schemas/PingResponse'
// → Promise<PingResponse>

// Inline object
responses:
  '200':
    content:
      application/json:
        schema:
          type: object
          properties:
            data: { type: string }
// → Promise<unknown> (or generate inline type)

// Array response
responses:
  '200':
    content:
      application/json:
        schema:
          type: array
          items:
            $ref: '#/components/schemas/NewsItem'
// → Promise<NewsItem[]>

// No content
responses:
  '204':
    description: Deleted successfully
// → Promise<void>
```

**Handling Multiple Content Types:**
- Prefer `application/json`
- Ignore other content types (text/html, application/xml)
- Default to `unknown` if no JSON response

```typescript
 * @example
 * const news = await sdk.general.getNews({ from: '2024-01-01' });
 * console.log(news.data.length);
 */
```

**JSDoc Content Sources:**

| JSDoc Element | OpenAPI Source | Fallback |
|---------------|----------------|----------|
| Summary | `operation.summary` | Method name description |
| Description | `operation.description` | Omit if missing |
| @param | `parameter.description` | Parameter name only |
| @returns | `response.description` | Generic "Response data" |
| @throws | Standard SDK errors | Always include all 4 |
| @see | `operation.externalDocs.url` | Omit if missing |
| @example | Generated from method signature | Always generate |

**Example Generation:**
- Use method name and signature to create realistic example
- Show parameter usage
- Show response property access
- Keep examples simple and practical

### Base URL Detection

**Multi-Domain Architecture:**

Wildberries APIs use different base URLs per API category:

| Module | Base URL | Source |
|--------|----------|--------|
| general | https://common-api.wildberries.ru | path-level servers |
| products | https://content-api.wildberries.ru | path-level servers |
| ordersFBS | https://marketplace-api.wildberries.ru | path-level servers |
| finances | https://finance-api.wildberries.ru | path-level servers |
| analytics | https://seller-analytics-api.wildberries.ru | path-level servers |

**Detection Strategy:**

```typescript
function detectBaseUrl(operation: ParsedOperation, specServers: ServerObject[]): string {
  // 1. Check path-level servers (highest priority)
  if (operation.servers && operation.servers.length > 0) {
    return operation.servers[0].url;
  }

  // 2. Fallback to spec-level servers
  if (specServers && specServers.length > 0) {
    return specServers[0].url;
  }

  // 3. Default (should never happen with valid OpenAPI)
  return 'https://api.wildberries.ru';
}
```

**URL Construction:**
```typescript
const baseUrl = detectBaseUrl(operation); // 'https://common-api.wildberries.ru'
const path = operation.path;              // '/ping'
const fullUrl = `${baseUrl}${path}`;      // 'https://common-api.wildberries.ru/ping'
```

**Important:** Do NOT hardcode base URLs. Always extract from OpenAPI `servers` config.

[Source: architecture.md#Multi-Domain Base URLs, .claude/CLAUDE.md#Multi-Domain Base URLs]

### BaseClient Delegation Pattern

**All module methods delegate to BaseClient:**

```typescript
export class GeneralModule {
  constructor(private client: BaseClient) {}

  async methodName(...params): Promise<ResponseType> {
    return this.client.httpMethod<ResponseType>(url, data?, options?);
  }
}
```

**HTTP Method Mapping:**

| OpenAPI Method | BaseClient Method | Has Request Body? |
|----------------|-------------------|-------------------|
| `get` | `client.get()` | No |
| `post` | `client.post()` | Yes |
| `put` | `client.put()` | Yes |
| `patch` | `client.patch()` | Yes |
| `delete` | `client.delete()` | Usually no |

**Method Signatures:**

```typescript
// GET request (no body)
this.client.get<ResponseType>(url, options?)

// POST request (with body)
this.client.post<ResponseType>(url, data, options?)

// Query parameters passed via options
this.client.get<ResponseType>(url, { params: queryParams })

// Rate limit key passed via options
this.client.post<ResponseType>(url, data, { rateLimitKey: 'products.create' })
```

**Why Delegation?**
- BaseClient handles: authentication, retry, rate limiting, error transformation
- Modules focus only on: API endpoint mapping and type safety
- Single source of truth for HTTP infrastructure
- Consistent behavior across all modules

### Error Handling in Generator

**Graceful Degradation:**

1. **Missing operationId:**
   - Generate name from path + method
   - Log info: "Generated method name from path: {name}"

2. **No response schema:**
   - Default to `Promise<unknown>`
   - Log warning: "No response schema for {method} {path}"

3. **Invalid path format:**
   - Skip operation
   - Log error: "Invalid path format: {path}"
   - Continue with next operation

4. **Missing servers config:**
   - Use default base URL
   - Log warning: "No servers config for {path}, using default"

5. **Unsupported HTTP method:**
   - Skip operation
   - Log warning: "Unsupported HTTP method: {method}"

**Logging:**
- Success: "Generated {count} methods for {module}"
- Warning: Non-critical issues with workarounds
- Error: Critical issues that block generation
