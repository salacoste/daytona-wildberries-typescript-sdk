4. Handles variations in table formatting and missing rate limit data gracefully
5. Generates rate limit configuration map per endpoint
6. Outputs configuration to `src/config/rate-limits.ts` or embeds in module
7. Successfully parses rate limits from all endpoints in `01-general.yaml`
8. Falls back to conservative defaults when rate limit data missing or unparseable
9. Unit tests validate parsing logic with various description formats

### Architecture Overview

**Component: Rate Limit Parser**

**Location:** `tools/generators/rate-limit-parser.ts`

**Purpose:** Extract rate limit information from OpenAPI operation descriptions and generate TypeScript configuration

**Unique Challenge:**

Wildberries OpenAPI specs embed rate limits in **Russian text tables** within description fields. This is **NOT standard OpenAPI** - most APIs use extensions like `x-rate-limit`.

**Example from OpenAPI:**
```yaml
paths:
  /content/v2/cards/upload:
    post:
      description: |
        <div class="description_limit">
        Лимит запросов на один аккаунт продавца:
        | Период | Лимит | Интервал | Всплеск |
        | --- | --- | --- | --- |
        | 1 минута | 100 запросов | 600 миллисекунд | 5 запросов |
        </div>
```

**Parsing Flow:**
```
1. Extract description field from operation
2. Find rate limit table (search for "Лимит запросов" + table markers)
3. Strip HTML tags if present
4. Apply regex to parse table rows
5. Extract: period, limit, interval, burst
6. Convert Russian time units to numbers
7. Calculate requestsPerMinute
8. Convert interval to seconds
9. Generate RateLimitConfig object
10. Write to src/config/{module}-rate-limits.ts
```

### Russian Rate Limit Table Format

**Standard Format:**

```
| Период | Лимит | Интервал | Всплеск |
| --- | --- | --- | --- |
| {period_value} {period_unit} | {limit_value} запросов | {interval_value} {interval_unit} | {burst_value} запросов |
```

**Real Examples:**

| Example | Period | Limit | Interval | Burst |
|---------|--------|-------|----------|-------|
| Products (strict) | 1 минута | 6 запросов | 10 секунд | 1 запрос |
| Products (general) | 1 минута | 100 запросов | 600 миллисекунд | 5 запросов |
| General (ping) | Not specified | Default | Default | Default |
| Orders | 1 минута | 30 запросов | 2 секунды | 10 запросов |

**Table Variations:**

1. **HTML Wrapping:**
   - Tables often wrapped in `<div class="description_limit">`
   - Links may be present: `<a href="...">Лимит запросов</a>`
   - Must strip HTML before parsing

2. **Whitespace Variations:**
   - Spaces vs tabs in table
   - Different separator styles (`---` vs `___`)
   - Extra newlines

3. **Plural Forms (Russian):**
   - запрос (singular) / запроса (2-4) / запросов (5+)
   - минута (singular) / минуты (2-4) / минут (5+)
   - секунда / секунды / секунд
   - миллисекунда / миллисекунды / миллисекунд

4. **Missing Tables:**
   - Some endpoints have no rate limit specified
   - Must use conservative defaults

### Time Unit Conversion

**Russian Time Units:**

| Russian | English | Conversion Factor | Example |
|---------|---------|-------------------|---------|
| миллисекунд(а/ы) | millisecond(s) | ÷ 1000 | 600 миллисекунд = 0.6 seconds |
| секунд(а/ы) | second(s) | × 1 | 20 секунд = 20 seconds |
| минут(а/ы) | minute(s) | × 60 | 1 минута = 60 seconds |
| час(ов/а) | hour(s) | × 3600 | 1 час = 3600 seconds |

**Conversion Algorithm:**

```typescript
function convertToSeconds(value: number, unit: string): number {
  const normalized = unit.toLowerCase();

  if (normalized.includes('миллисекунд')) {
    return value / 1000;
  }

  if (normalized.includes('секунд')) {
    return value;
  }

  if (normalized.includes('минут')) {
    return value * 60;
  }

  if (normalized.includes('час')) {
    return value * 3600;
  }

  // Default: assume seconds
  console.warn(`Unknown time unit: ${unit}, treating as seconds`);
  return value;
}
```

**Why Case-Insensitive Substring Matching?**
- Handles all plural forms automatically
- "минута", "минуты", "минут" all contain "минут"
- Case variations in OpenAPI descriptions

### Regex Pattern Explanation

**Complete Pattern:**

```typescript
const rateLimitRegex = /
  Период[\s|]*Лимит[\s|]*Интервал[\s|]*Всплеск[\s|]*  // Header row
  [\n\r]+                                              // Newline
  [\s|]*-+[\s|]*-+[\s|]*-+[\s|]*-+[\s|]*              // Separator row
  [\n\r]+                                              // Newline
  [\s|]*(\d+)\s+(минута|минуты|минут|секунд|секунды|секунда)  // Period
  [\s|]*(\d+)\s+(запросов|запроса|запрос)             // Limit
  [\s|]*(\d+)\s+(миллисекунд|миллисекунды|миллисекунда|секунд|секунды|секунда)  // Interval
  [\s|]*(\d+)\s+(запросов|запроса|запрос)             // Burst
/i;
```

**Capture Groups:**

1. **Group 1:** Period value (e.g., "1")
2. **Group 2:** Period unit (e.g., "минута")
3. **Group 3:** Limit value (e.g., "100")
4. **Group 4:** "запросов" (discard)
5. **Group 5:** Interval value (e.g., "600")
6. **Group 6:** Interval unit (e.g., "миллисекунд")
7. **Group 7:** Burst value (e.g., "5")
8. **Group 8:** "запросов" (discard)

**Pattern Features:**

- **[\s|]***: Matches whitespace or pipe characters (table column separators)
- **[\n\r]+**: Matches newlines (Unix, Windows, Mac)
- **-+**: Matches separator dashes (one or more)
- **\d+**: Matches numbers (one or more digits)
- **Plural variations**: Explicitly listed for accuracy
- **/i flag**: Case-insensitive matching

**Why Not Simpler Pattern?**

The table format has strict structure - we need to ensure we're parsing the correct row (data row, not header). The full pattern prevents false matches.

[Source: .claude/CLAUDE.md#Rate Limit Parsing]

### Conservative Default Values

**Default Configuration:**

```typescript
const DEFAULT_RATE_LIMIT_CONFIG: RateLimitConfig = {
  requestsPerMinute: 10,      // 1 request every 6 seconds
  intervalSeconds: 6,         // Enforced 6s minimum interval
  burstLimit: 5               // Allow 5 rapid requests initially
};
```

**Why These Defaults?**

1. **requestsPerMinute: 10**
   - Conservative rate that won't trigger most API limits
   - Gives headroom for actual limits (which are often higher)
   - Safe for production use without risk of API bans

2. **intervalSeconds: 6**
   - Enforces minimum spacing between requests
   - Prevents accidental bursting
   - Industry standard for "be gentle" rate

3. **burstLimit: 5**
   - Allows initial burst of requests
   - Useful for application startup
   - Not so high that it risks limits

**When Defaults Are Used:**

- No rate limit table found in operation description
- Regex parsing fails (malformed table)
- Extracted values invalid (zero, negative, impossible)
- HTML parsing fails
- Description field missing

**Logging Strategy:**

```typescript
if (!rateLimitInfo) {
  console.warn(
    `No rate limit found for ${operationId}, using conservative defaults:`,
    DEFAULT_RATE_LIMIT_CONFIG
  );
}
```

**User Override:**

Users can override defaults via SDKConfig:
```typescript
const sdk = new WildberriesSDK({
  apiKey: 'key',
  rateLimitConfig: {
    requestsPerMinute: 20  // Override global default
  }
});
```

   - Try without HTML stripping
   - Fallback to defaults if still fails

- Info: "Parsed rate limit for {endpoint}: {config}"
