# 9.9: Promotion Module - SDK Type & Parameter Fixes

## Status

**✅ COMPLETED** - December 23, 2025

---

## Summary

Comprehensive analysis and fix of all 42 Promotion module methods against Swagger documentation. Fixed:
1. **35 JSDoc examples** - Changed incorrect namespace from `sdk.general.*` to `sdk.promotion.*`
2. **18 methods with optional params** - Made required parameters mandatory
3. **3 Calendar API methods** - Added proper TypeScript return types

---

## Background

During Epic 9 comprehensive testing of all 42 Promotion module methods, systematic issues were discovered:

1. **Code Generator Issue**: All auto-generated JSDoc examples used `sdk.general.*` namespace instead of module-specific `sdk.promotion.*`

2. **Optional vs Required**: Many methods marked required API parameters as optional, allowing TypeScript compilation of invalid API calls

3. **Missing Return Types**: Calendar API methods used `Promise<unknown>` instead of proper typed responses

**API Documentation**: https://dev.wildberries.ru/openapi/promotion

---

## Impact

### Breaking Changes

Methods that previously accepted `undefined` for required parameters will now cause TypeScript compilation errors:

```typescript
// Before (compiled but failed at runtime)
await sdk.promotion.getAdvBudget(); // ❌ Now TypeScript error

// After (correct usage)
await sdk.promotion.getAdvBudget({ id: 12345 }); // ✅ Compiles and works
```

### Improved Type Safety

Calendar API methods now provide type hints:

```typescript
const promotions = await sdk.promotion.getCalendarPromotions({
  startDateTime: '2024-01-01',
  endDateTime: '2024-12-31',
  allPromo: true
});

// Now has proper autocomplete
promotions.data?.promotions?.forEach(p => {
  console.log(p.name); // ✅ TypeScript knows about p.name
});
```
