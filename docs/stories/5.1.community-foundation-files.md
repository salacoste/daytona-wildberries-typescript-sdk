## Dev Notes

### Community File Standards

**Contributor Covenant 2.1:**
- Source: https://www.contributor-covenant.org/version/2/1/code_of_conduct/
- Industry standard for open-source projects
- Used by 100,000+ open-source projects

**GitHub Community Health Files:**
- Location: Repository root or .github/ directory
- Recognized by GitHub's community health tools
- Enables GitHub's community insights and recommendations

[Source: GitHub Docs - Creating a default community health file]

### CONTRIBUTING.md Structure

**Recommended Sections:**

1. **Welcome Message** - Encourage contributions
2. **Getting Started** - Setup instructions for development environment
   ```bash
   git clone https://github.com/yourusername/wb-api-sdk.git
   cd wb-api-sdk
   npm install
   npm test
   ```
3. **Development Workflow**
   - Branch naming: `feature/add-analytics-endpoint`, `bugfix/fix-rate-limiter`
   - Commit messages: Conventional commits format
     - `feat: add support for Tariffs module`
     - `fix: resolve rate limit edge case in BaseClient`
     - `docs: update API reference for Products module`
   - Pre-commit checks: `npm run type-check && npm run lint && npm test`

4. **Code Standards**
   - TypeScript strict mode (zero `any` types)
   - ESLint + Prettier (auto-formatted on commit)
   - Naming conventions: PascalCase (classes), camelCase (functions), SCREAMING_SNAKE_CASE (constants)
   - File structure: Follow existing patterns in src/modules/, src/client/

5. **Testing Requirements**
   - Unit tests required for all new code (≥80% coverage)
   - Integration tests for API endpoints (MSW mocking)
   - Test file naming: `{component}.test.ts` alongside source files
   - Follow AAA pattern: Arrange, Act, Assert

6. **Pull Request Process**
   - Fork repository → Create feature branch → Make changes → Run tests → Submit PR
   - PR title: Descriptive summary (e.g., "Add Tariffs module with commission rate queries")
   - PR description: Use template (auto-populated)
   - Review process: 1-2 maintainers review, feedback addressed, CI passes, merge

7. **Communication**
   - Questions: GitHub Discussions or Issues with "question" label
   - Bug reports: GitHub Issues with bug template
   - Feature requests: GitHub Issues with feature template

[Source: architecture.md#Coding Standards + Test Strategy]

### CODE_OF_CONDUCT.md Key Points

**Enforcement Contacts:**
- Primary: [project-email]@example.com
- Backup: GitHub Security Advisories

**Enforcement Actions:**
1. **Warning** - Private written warning with clarity on violation
2. **Temporary Ban** - Temporary ban from interaction (1 week - 1 month)
3. **Permanent Ban** - Permanent ban from all project spaces

**Scope:**
- GitHub repository (issues, PRs, discussions)
- Project communication channels
- Representing project in public spaces

[Source: Contributor Covenant 2.1]

### SECURITY.md Structure

**Supported Versions:**

| Version | Supported |
|---------|-----------|
| 1.0.x   | ✅ Yes    |
| < 1.0   | ❌ No     |

**Reporting a Vulnerability:**

1. **Do NOT** create public GitHub issue for security vulnerabilities
2. Email security@[project-domain].com with:
   - Description of vulnerability
   - Steps to reproduce
   - Potential impact
   - Suggested fix (if available)
3. Expect acknowledgment within 24-48 hours
4. Coordinated disclosure timeline: 90 days from report

**Security Best Practices for SDK Users:**
- Never commit API keys to version control
- Use environment variables for sensitive data
- Rotate API keys regularly
- Enable HTTPS for all API communications
- Validate rate limit responses to prevent abuse

[Source: architecture.md#Security]

### GitHub Issue Templates

**Template Format:** YAML frontmatter + Markdown body

**Bug Report Template (.github/ISSUE_TEMPLATE/bug_report.yml):**
```yaml
name: Bug Report
description: Report a bug or unexpected behavior
title: "[Bug]: "
labels: ["bug", "needs-triage"]
body:
  - type: markdown
    attributes:
      value: |
        Thanks for reporting a bug! Please provide as much detail as possible.

  - type: textarea
    id: description
    attributes:
      label: Bug Description
      description: Clear description of the bug
    validations:
      required: true

  - type: textarea
    id: steps
    attributes:
      label: Steps to Reproduce
      description: Detailed steps to reproduce the issue
      placeholder: |
        1. Initialize SDK with '...'
        2. Call method '...'
        3. See error
    validations:
      required: true

  - type: textarea
    id: expected
    attributes:
      label: Expected Behavior
      description: What you expected to happen
    validations:
      required: true

  - type: textarea
    id: actual
    attributes:
      label: Actual Behavior
      description: What actually happened
    validations:
      required: true

  - type: textarea
    id: environment
    attributes:
      label: Environment
      description: Your development environment details
      value: |
        - OS: [e.g., macOS 14.0, Ubuntu 22.04, Windows 11]
        - Node.js version: [e.g., 20.11.1]
        - SDK version: [e.g., 1.0.0]
        - Package manager: [e.g., npm 10.2.4]
    validations:
      required: true

  - type: textarea
    id: logs
    attributes:
      label: Logs and Screenshots
      description: Any relevant logs, error messages, or screenshots
      placeholder: Paste logs or attach screenshots here
```
