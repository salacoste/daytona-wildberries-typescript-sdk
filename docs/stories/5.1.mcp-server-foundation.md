## Story

**As a** AI agent developer (building tools with Claude Code, Cline, etc.),
**I want** to connect to a Wildberries API MCP server that exposes core SDK operations,
**so that** I can perform marketplace operations through natural language without writing custom integration code.

## Acceptance Criteria

**Functional Requirements:**

1. MCP server project initialized with TypeScript configuration matching SDK standards (strict mode, ESLint, Vitest)
2. MCP protocol transport implemented (stdio) with proper connection handling and graceful shutdown
3. Tool discovery endpoint returns JSON schema for available tools
4. `ping` tool implemented exposing `sdk.general.ping()` with proper parameter/response mapping
5. `list_products` tool implemented exposing `sdk.products.listProducts()` with filter parameters
6. `get_order` tool implemented exposing `sdk.ordersFBS.getOrderById()` with orderId parameter
7. Tool execution properly delegates to SDK methods, inheriting rate limiting and error handling
8. SDK configuration accepted via MCP server initialization (API key from environment or config file)

**Integration Requirements:**

9. Wildberries SDK imported as dependency, zero modifications to SDK source code
10. MCP tools inherit SDK error handling (AuthenticationError, RateLimitError, ValidationError properly surfaced)
11. Rate limiting enforced through SDK's existing RateLimiter (no bypass possible via MCP layer)
12. Existing SDK functionality verified unchanged through regression test suite

**Quality Requirements:**

13. Unit tests validate MCP tool schema generation and parameter mapping
14. Integration tests validate complete flow: MCP tool call → SDK method → mocked API response
15. README.md created with setup instructions for Claude Desktop configuration
16. Tool documentation includes parameter descriptions and example natural language prompts

## Dev Notes

### Project Context

This story implements the foundation of an MCP (Model Context Protocol) server that wraps the Wildberries TypeScript SDK, exposing SDK functionality as MCP tools for AI agent consumption. The MCP server is a **separate layer** that imports and delegates to the existing SDK without modifying core SDK code.

### Relevant SDK Architecture

**SDK Main Class Structure:**
```typescript
// src/index.ts
export class WildberriesSDK {
  public readonly general: GeneralModule;
  public readonly products: ProductsModule;
  public readonly ordersFBS: OrdersFBSModule;
  // ... 8 more modules

  constructor(config: SDKConfig) {
    const client = new BaseClient(config);
    this.general = new GeneralModule(client);
    // ... initialize modules
  }
}

// SDKConfig interface
interface SDKConfig {
  apiKey: string;              // REQUIRED
  timeout?: number;            // Default: 30000ms
  retryConfig?: RetryConfig;
  rateLimitConfig?: RateLimitConfig;
  logLevel?: 'debug' | 'info' | 'warn' | 'error';
}
```

**SDK Error Hierarchy:**
```typescript
WBAPIError (base)
  ├── AuthenticationError (401, 403)
  ├── RateLimitError (429, includes retryAfter milliseconds)
  ├── ValidationError (400, 422, includes field errors)
  └── NetworkError (timeouts, 5xx, includes isTimeout flag)
```

**Module Pattern:**
All SDK modules delegate to BaseClient and return Promise<T> with typed responses:
```typescript
class ProductsModule {
  constructor(private client: BaseClient) {}

  async listProducts(filters?: ProductFilters): Promise<ProductListResponse> {
    return this.client.get<ProductListResponse>('/products', filters);
  }
}
```

**Tool Definition Pattern:**
```typescript
// mcp-server/src/tools/ping.ts
import { Tool } from '@modelcontextprotocol/sdk/types.js';

export const pingTool: Tool = {
  name: 'ping',
  description: 'Test connectivity to Wildberries API and verify authentication',
  inputSchema: {
    type: 'object',
    properties: {}, // No parameters for ping
    required: []
  }
};

export async function executePing(sdk: WildberriesSDK, args: any) {
  const result = await sdk.general.ping();
  return {
    content: [
      {
        type: 'text',
        text: JSON.stringify(result, null, 2)
      }
    ]
  };
}
```

### Required MCP SDK Dependency

Install MCP SDK:
```bash
npm install @modelcontextprotocol/sdk
```

**MCP Server Implementation Pattern:**
```typescript
// mcp-server/src/server.ts
import { Server } from '@modelcontextprotocol/sdk/server/index.js';
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js';
import { WildberriesSDK } from 'daytona-wildberries-typescript-sdk';

export class WildberriesMCPServer {
  private server: Server;
  private sdk: WildberriesSDK;

  constructor(apiKey: string) {
    this.sdk = new WildberriesSDK({ apiKey });
    this.server = new Server({
      name: 'wildberries-api-server',
      version: '1.0.0'
    }, {
      capabilities: {
        tools: {}
      }
    });

    this.setupToolHandlers();
  }

  private setupToolHandlers() {
    this.server.setRequestHandler('tools/list', async () => ({
      tools: [pingTool, listProductsTool, getOrderTool]
    }));

    this.server.setRequestHandler('tools/call', async (request) => {
      // Route to appropriate tool handler
    });
  }

  async start() {
    const transport = new StdioServerTransport();
    await this.server.connect(transport);
  }
}
```

### Error Handling Requirements

**MCP Error Response Format:**
```typescript
// Transform SDK errors to MCP errors
try {
  const result = await sdk.products.listProducts(filters);
  return { content: [{ type: 'text', text: JSON.stringify(result) }] };
} catch (error) {
  if (error instanceof AuthenticationError) {
    throw {
      code: -32001,
      message: 'Authentication failed',
      data: { detail: error.message }
    };
  }
  if (error instanceof RateLimitError) {
    throw {
      code: -32002,
      message: 'Rate limit exceeded',
      data: { retryAfter: error.retryAfter }
    };
  }
  // ... handle other SDK error types
}
```

### Configuration Management

**Environment Variable Loading:**
```typescript
// mcp-server/src/config.ts
export interface MCPServerConfig {
  apiKey: string;
  sdkTimeout?: number;
  logLevel?: 'debug' | 'info' | 'warn' | 'error';
}

export function loadConfig(): MCPServerConfig {
  const apiKey = process.env.WB_API_KEY;
  if (!apiKey) {
    throw new Error('WB_API_KEY environment variable required');
  }

  return {
    apiKey,
    sdkTimeout: parseInt(process.env.WB_SDK_TIMEOUT || '30000'),
    logLevel: (process.env.WB_LOG_LEVEL as any) || 'warn'
  };
}
```

#### Test Patterns

**Unit Test Example:**
```typescript
// mcp-server/tests/unit/tools/ping.test.ts
import { describe, it, expect, vi } from 'vitest';
import { executePing } from '../../../src/tools/ping';
import type { WildberriesSDK } from 'daytona-wildberries-typescript-sdk';

describe('ping tool', () => {
  it('should call sdk.general.ping and return formatted response', async () => {
    const mockSdk = {
      general: {
        ping: vi.fn().mockResolvedValue({ status: 'ok', timestamp: '2024-10-19T12:00:00Z' })
      }
    } as unknown as WildberriesSDK;

    const result = await executePing(mockSdk, {});

    expect(mockSdk.general.ping).toHaveBeenCalledOnce();
    expect(result.content[0].type).toBe('text');
    expect(JSON.parse(result.content[0].text)).toEqual({
      status: 'ok',
      timestamp: '2024-10-19T12:00:00Z'
    });
  });
});
```

**Integration Test Example:**
```typescript
// mcp-server/tests/integration/server.test.ts
import { describe, it, expect, beforeAll, afterAll } from 'vitest';
import { WildberriesMCPServer } from '../../src/server';

describe('MCP Server Integration', () => {
  let server: WildberriesMCPServer;

  beforeAll(async () => {
    server = new WildberriesMCPServer('test-api-key');
    await server.start();
  });

  afterAll(async () => {
    await server.stop();
  });

  it('should list available tools', async () => {
    const tools = await server.handleToolsList();
    expect(tools).toHaveLength(3);
    expect(tools.map(t => t.name)).toEqual(['ping', 'list_products', 'get_order']);
  });
});
```

### Important Implementation Notes

1. **Zero SDK Modifications:** Import SDK as dependency, never modify source
2. **Rate Limiting Inheritance:** All rate limiting happens in SDK's RateLimiter
3. **Error Preservation:** Preserve full SDK error context when transforming to MCP errors
4. **Type Safety:** Use SDK's exported TypeScript types for all data structures
5. **Context7 Usage:** Query Context7 for MCP SDK patterns before implementation
6. **Logging:** Use same logging patterns as SDK (structured logs, no PII)
