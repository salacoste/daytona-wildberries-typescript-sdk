# Story 2.4: Products Module - Warehouse and Stock Management

---

## Status

**Done**

---

## Story

**As a** marketplace seller,
**I want** to manage warehouse assignments and stock levels,
**so that** I can control inventory distribution and availability.

---

## Acceptance Criteria

1. `getWBOffices()` method retrieves available Wildberries warehouses for FBS binding
2. `getWarehouses()` method retrieves seller's warehouse list
3. `createWarehouse(name: string, officeId: number)` method creates seller warehouse bound to WB office
4. `updateWarehouse(warehouseId: number, data: WarehouseUpdate)` method updates warehouse details
5. `deleteWarehouse(warehouseId: number)` method removes warehouse from seller's list
6. `getStock(warehouseId: number, skus: string[])` method retrieves stock levels for products
7. `updateStock(warehouseId: number, updates: StockUpdate[])` method updates stock quantities (bulk)
8. `deleteStock(warehouseId: number, skus: string[])` method removes stock records (bulk)
9. Stock updates support bulk operations (1-1000 SKUs) with proper error handling per item
10. Warehouse creation validates WB office binding constraints (no duplicate bindings)
11. Rate limits enforced for warehouse and stock operations (300 req/min, 200ms interval)
12. Unit tests validate all warehouse and stock method contracts
13. Integration tests with MSW validate complete warehouse setup and stock management flows
14. Example code demonstrates inventory management workflow

### API Specifications

**Base URL**: `https://marketplace-api.wildberries.ru` (different from content-api!)
[Source: OpenAPI spec wildberries_api_doc/02-products.yaml, lines 4051, 4359]

**WB Offices Endpoints**:

1. **GET /api/v3/offices** - Get WB Warehouses List
   - **Purpose**: Get available Wildberries warehouses for binding to seller warehouses
   - **Used for**: FBS (Fulfillment by Seller) model - seller delivers to WB warehouse
   - **Returns**: Array of WB offices with `id`, `name`, `address`
   - **Rate limit**: 300 req/min, 200ms interval, 20 burst
   [Source: Lines 4319-4356 in 02-products.yaml]

**Warehouse Endpoints**:

2. **GET /api/v3/warehouses** - Get Seller Warehouses
   - **Returns**: Array of seller warehouses (schema: `Warehouse`)
   - **Fields**: `id`, `name`, `officeId`, `isActive`
   - **Rate limit**: 300 req/min, 200ms interval, 20 burst
   [Source: Lines 4357-4394 in 02-products.yaml]

3. **POST /api/v3/warehouses** - Create Seller Warehouse
   - **Request body**: `{ name: string, officeId: number }`
   - **Validation**: name 1-200 chars, officeId must be positive integer
   - **Returns**: `{ id: number }` (201 Created)
   - **CRITICAL**: Cannot bind WB office already in use (409 error)
   - **Purpose**: Create warehouse for FBS model
   - **Rate limit**: 300 req/min, 200ms interval, 20 burst
   [Source: Lines 4395-4477 in 02-products.yaml]

4. **PUT /api/v3/warehouses/{warehouseId}** - Update Warehouse
   - **Path param**: `warehouseId` (seller warehouse ID)
   - **Request body**: `{ name: string, officeId: number }`
   - **Returns**: 204 No Content
   - **CRITICAL**: Office binding can only be changed once per 24 hours
   - **Cannot**: Reuse WB office already bound elsewhere
   - **Rate limit**: 300 req/min, 200ms interval, 20 burst
   [Source: Lines 4478-4555 in 02-products.yaml]

5. **DELETE /api/v3/warehouses/{warehouseId}** - Delete Warehouse
   - **Path param**: `warehouseId`
   - **Returns**: 204 No Content
   - **Effect**: Unbinds WB office for reuse
   - **Rate limit**: 300 req/min, 200ms interval, 20 burst
   [Source: Lines 4556+ in 02-products.yaml]

**Stock Endpoints**:

6. **POST /api/v3/stocks/{warehouseId}** - Get Stock Levels
   - **Path param**: `warehouseId` (seller warehouse ID)
   - **Request body**: `{ skus: string[] }` (1-1000 SKUs)
   - **Returns**: `{ stocks: [{ sku: string, amount: number }] }`
   - **Rate limit**: 300 req/min, 200ms interval, 20 burst
   [Source: Lines 4236-4298 in 02-products.yaml]

7. **PUT /api/v3/stocks/{warehouseId}** - Update Stock Quantities
   - **Path param**: `warehouseId`
   - **Request body**: `{ stocks: [{ sku: string, amount: number }] }` (1-1000 items)
   - **Validation**: amount must be 0-100,000
   - **Returns**: 204 No Content
   - **CRITICAL**: Parameter names NOT validated - incorrect names = silent failure with 200 OK
   - **409 Errors**: DBS/FBS restrictions, cargo type restrictions, warehouse processing
   - **Rate limit**: 300 req/min, 200ms interval, 20 burst
   - **Special**: 409 errors count as 5 requests toward rate limit
   [Source: Lines 4049-4151 in 02-products.yaml]

8. **DELETE /api/v3/stocks/{warehouseId}** - Delete Stock Records
   - **Path param**: `warehouseId`
   - **Request body**: `{ skus: string[] }` (1-1000 SKUs)
   - **Returns**: 204 No Content
   - **IRREVERSIBLE**: Deleted stock must be re-uploaded to resume sales
   - **404**: Returns SKUs not found
   - **409**: Warehouse processing in progress

### Critical Implementation Notes

**1. Different Base URL - Marketplace API** ⚠️

Warehouse and stock endpoints use `marketplace-api.wildberries.ru`, NOT `content-api.wildberries.ru` like other Products methods.

**Why**: Warehouses are part of marketplace fulfillment infrastructure, not content management.

[Source: Lines 4051, 4321, 4359 in 02-products.yaml - servers field]

**2. WB Office Binding Constraints** 🔒

- **Cannot bind office already in use**: 409 error if WB office bound to another warehouse
- **Once per 24 hours**: Office binding can only be changed once every 24 hours
- **Purpose**: WB offices enable FBS (Fulfillment by Seller) model

**Example**:
```typescript
// Get available WB offices
const offices = await sdk.products.getWBOffices();

// Create warehouse with office binding
try {
  const warehouse = await sdk.products.createWarehouse('Склад 1', offices[0].id);

  if (error.statusCode === 409) {
    console.error('Office already bound to another warehouse');
  }
}
```

[Source: Lines 4404-4406, 4490-4492 in 02-products.yaml]

**3. Silent Failure on Incorrect Parameters** 🚨

Stock update (PUT /api/v3/stocks/{warehouseId}) does NOT validate parameter names. Incorrect field names result in 200 OK response but no actual update.

**Example**:
```typescript
// WRONG - Returns 200 OK but doesn't update stock
await updateStock(warehouseId, {
  stock: [{ barcode: 'SKU1', qty: 100 }]  // Wrong field names!
});

// CORRECT
await updateStock(warehouseId, {
  stocks: [{ sku: 'SKU1', amount: 100 }]  // Correct field names
});
```

[Source: Lines 4061-4063 in 02-products.yaml - description warning]

**4. 409 Errors Count as 5 Requests** 💥

409 (Conflict) responses count as **5 requests** toward the rate limit instead of 1.

**When 409 occurs**:
- DBS/FBS warehouse restrictions
- Cargo type warehouse restrictions (LCL, ODC, CD+)
- Warehouse processing in progress
- WB office already bound

**Impact**: Can quickly exhaust rate limit if bulk operations trigger conflicts.

[Source: Lines 4072, 4172, 4252, 4376, 4415, 4501 in 02-products.yaml - rate limit tables]

**5. Stock Deletion is Irreversible** ⚠️

DELETE /api/v3/stocks/{warehouseId} permanently removes stock records. To resume sales, stock must be re-uploaded.

**Example**:
```typescript

await sdk.products.deleteStock(warehouseId, ['SKU123']);
// SKU123 stock is gone - must upload again to sell
```

- **Max per SKU**: 100,000

- **Values**: Must be non-negative integers
