## Error Handling

### SDK Error Hierarchy

The SDK provides a comprehensive error hierarchy for precise error handling:

\`\`\`typescript
import {
  WBAPIError,           // Base error class
  AuthenticationError,  // 401 errors
  RateLimitError,      // 429 errors
  ValidationError,     // 400 errors
  NetworkError         // Network failures
} from 'wb-api-sdk';
\`\`\`

### Error Handling Pattern

\`\`\`typescript
async function robustAPICall() {
  try {
    const result = await sdk.products.getParentCategories();
    return { success: true, data: result };

  } catch (error) {
    // Handle specific SDK errors
    if (error instanceof RateLimitError) {
      // SDK automatically retries, but you can add custom logic
      logger.warn('Rate limit hit', {
        retryAfter: error.retryAfter,
        endpoint: 'getParentCategories'
      });
      // Option: Implement backpressure mechanism

    } else if (error instanceof AuthenticationError) {
      // Don't retry authentication errors
      logger.error('Authentication failed', { error });
      throw new Error('Invalid API credentials');

    } else if (error instanceof ValidationError) {
      // Log validation details for debugging
      logger.error('Validation error', {
        message: error.message,
        details: error.details
      });
      throw error;

    } else if (error instanceof NetworkError) {
      // Implement retry with exponential backoff
      logger.error('Network error', { error });
      // See retry logic section

    } else {
      // Unexpected error
      logger.error('Unexpected error', { error });
      throw error;
    }
  }
}
\`\`\`

### Batch Operation Strategy

For high-volume operations:

\`\`\`typescript
async function batchUpdatePrices(updates: PriceUpdate[]) {
  const batchSize = 10;
  const delayMs = 1000;

  for (let i = 0; i < updates.length; i += batchSize) {
    const batch = updates.slice(i, i + batchSize);

    await Promise.all(
      batch.map(update => sdk.products.updatePrice(update))
    );

    // Respect rate limits between batches
    if (i + batchSize < updates.length) {
      await sleep(delayMs);
    }
  }
}

## Retry Logic

### SDK's Automatic Retry

The SDK implements exponential backoff for transient errors:

\`\`\`typescript
// Default retry configuration
const sdk = new WildberriesSDK({
  apiKey: process.env.WB_API_KEY,
  retryConfig: {
    maxRetries: 3,
    retryDelay: 1000,      // Initial delay: 1s
    exponentialBackoff: true,
    maxRetryDelay: 32000   // Cap at 32s
  }
});
\`\`\`

**Backoff Algorithm:**
- Attempt 1: Wait 1s (1000ms)
- Attempt 2: Wait 2s (2000ms)
- Attempt 3: Wait 4s (4000ms)

### Custom Retry Implementation

For advanced use cases:

\`\`\`typescript
async function retryWithJitter<T>(
  operation: () => Promise<T>,
  options = { maxRetries: 3, baseDelay: 1000 }
): Promise<T> {
  for (let attempt = 0; attempt <= options.maxRetries; attempt++) {
    try {
      return await operation();
    } catch (error) {
      if (attempt === options.maxRetries) throw error;

      // Don't retry non-retryable errors
      if (error instanceof AuthenticationError ||
          error instanceof ValidationError) {
        throw error;
      }

      // Exponential backoff with jitter
      const exponentialDelay = options.baseDelay * Math.pow(2, attempt);
      const jitter = Math.random() * 1000; // 0-1000ms jitter
      const delay = exponentialDelay + jitter;

      logger.info(\`Retry attempt \${attempt + 1} after \${delay}ms\`);
      await sleep(delay);
    }
  }
}
\`\`\`

### Circuit Breaker Pattern

Prevent cascading failures:

\`\`\`typescript
class CircuitBreaker {
  private failures = 0;
  private state: 'closed' | 'open' | 'half-open' = 'closed';
  private threshold = 5;
  private timeout = 60000; // 1 minute

  async execute<T>(operation: () => Promise<T>): Promise<T> {
    if (this.state === 'open') {
      throw new Error('Circuit breaker is open');
    }

    try {
      const result = await operation();
      this.onSuccess();
      return result;
    } catch (error) {
      this.onFailure();
      throw error;
    }
  }

  private onSuccess() {
    this.failures = 0;
    if (this.state === 'half-open') {
      this.state = 'closed';
    }
  }

  private onFailure() {
    this.failures++;
    if (this.failures >= this.threshold) {
      this.state = 'open';
      setTimeout(() => {
        this.state = 'half-open';
      }, this.timeout);
    }
  }
}
\`\`\`

## Logging & Monitoring

### Structured Logging

Use structured logging for better observability:

\`\`\`typescript
import winston from 'winston';

const logger = winston.createLogger({
  level: process.env.LOG_LEVEL || 'info',
  format: winston.format.combine(
    winston.format.timestamp(),
    winston.format.errors({ stack: true }),
    winston.format.json()

  defaultMeta: { service: 'wb-sdk-app' },
  transports: [
    new winston.transports.File({ filename: 'error.log', level: 'error' }),
    new winston.transports.File({ filename: 'combined.log' })
  ]
});

// Log API calls
logger.info('API call started', {
  module: 'products',
  method: 'getParentCategories',
  timestamp: Date.now()
});
\`\`\`

### What to Log

✅ **DO Log:**
- API call start/end times
- Error details with context
- Performance metrics
- Rate limit events
- Retry attempts

❌ **DON'T Log:**
- API keys or tokens
- Sensitive user data
- Full request/response bodies (unless debug mode)

### Monitoring Setup

**Key Metrics to Track:**

1. **API Call Metrics:**
   - Request rate (requests/second)
   - Success rate (%)
   - Error rate (%)
   - Latency (p50, p95, p99)

2. **Error Metrics:**
   - Error count by type
   - Rate limit hits
   - Retry attempts

3. **Business Metrics:**
   - Orders processed
   - Products synced
   - Revenue tracked

**Prometheus Example:**

\`\`\`

**Secret Management (Production):**

\`\`\`typescript
// AWS Secrets Manager example
import { SecretsManagerClient, GetSecretValueCommand } from '@aws-sdk/client-secrets-manager';

async function getAPIKey(): Promise<string> {
  const client = new SecretsManagerClient({ region: 'us-east-1' });
  const response = await client.send(
    new GetSecretValueCommand({ SecretId: 'wb-api-key' })
  );
  return JSON.parse(response.SecretString!).apiKey;
}

const apiKey = await getAPIKey();
const sdk = new WildberriesSDK({ apiKey });
\`\`\`

### Security Checklist

- [ ] **API Keys**
  - [ ] Never hardcode API keys in source code
  - [ ] Use environment variables or secret management
  - [ ] Rotate keys regularly (quarterly)
  - [ ] Revoke old keys immediately after rotation
  - [ ] Use different keys for development and production

- [ ] **Network Security**
  - [ ] Enforce HTTPS for all API calls (SDK default)
  - [ ] Validate TLS certificates
  - [ ] Use latest TLS version (1.3 preferred)
  - [ ] Implement IP whitelisting if possible

- [ ] **Data Protection**
  - [ ] Never log API keys or tokens
  - [ ] Sanitize error messages before logging
  - [ ] Encrypt sensitive data at rest
  - [ ] Use secure credential storage

- [ ] **Dependency Security**
  - [ ] Run `npm audit` regularly
  - [ ] Enable automated vulnerability scanning (Dependabot)
  - [ ] Keep SDK and dependencies updated
  - [ ] Review security advisories
