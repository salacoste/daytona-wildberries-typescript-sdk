## Story

**I want** to manage order status transitions through bulk and legacy APIs,
**So that** I can efficiently process order lifecycle from assembly to delivery confirmation.

---

## Context

### Background

DBS Status Management is critical for sellers who handle their own delivery. The order lifecycle follows a specific flow:

```
new -> confirm -> deliver -> receive (success)
                         \-> reject (customer refused)
new/confirm/deliver -> cancel (seller cancellation)
```

**API Evolution (14.01.2026)**:
- NEW: Bulk status methods (`/api/marketplace/v3/dbs/orders/status/*`) - recommended
- DEPRECATED: Single-order PATCH methods (will be disabled **13.04.2026**)

Sellers should migrate to bulk methods for better performance and future compatibility.

### Technical Context

**API Documentation**: `wildberries_api_doc/04-orders-dbs.yaml`
**Base URL**: `https://marketplace-api.wildberries.ru`

### Supplier Status Values

| Status | Description | Transition From |
| --- | --- | --- |
| `new` | New assembly task | Initial state |
| `confirm` | In assembly | `new` |
| `deliver` | In delivery | `confirm` |
| `receive` | Received by customer | `deliver` (requires code) |
| `reject` | Customer rejection on delivery | `deliver` (requires code) |
| `cancel` | Cancelled by seller | `new`, `confirm`, `deliver` |
| `canceled_by_missed_call` | Cancelled due to failed call | Automatic |

### WB Status Values

`waiting`, `sorted`, `sold`, `canceled`, `canceled_by_client`, `declined_by_client`, `defect`, `ready_for_pickup`, `canceled_by_missed_call`

  /**
   * Get statuses for multiple DBS orders (bulk)
   *
   * Returns supplier and WB statuses for up to 1000 orders.
   *
   * Rate limit: 300 req/min, 200ms interval, 20 burst
   *
   * @param orderIds - Array of order IDs (max 1000)
   * @returns Promise with order statuses
   * @throws {ValidationError} When orderIds exceeds 1000 items
   *
   * @see {@link https://dev.wildberries.ru/openapi/orders-dbs}
   *
   * @example
   * ```typescript
   * const statuses = await sdk.ordersDBS.getStatusesBulk([123456, 234567]);
   * statuses.orders.forEach(order => {
   *   console.log(`Order ${order.orderId}: ${order.supplierStatus}`);
   * });
   * ```
   */
  async getStatusesBulk(orderIds: number[]): Promise<{ orders: DBSOrderStatusBulk[] }> {
    if (orderIds.length > 1000) {
      throw new ValidationError('orderIds array cannot exceed 1000 items');
    }
    return this.client.post<{ orders: DBSOrderStatusBulk[] }>(
      'https://marketplace-api.wildberries.ru/api/marketplace/v3/dbs/orders/status/info',
      { ordersIds: orderIds },
      { rateLimitKey: 'orders-dbs.status.read' }
    );
  }
  ```

  import { WildberriesSDK } from '../src';

  async function dbsStatusWorkflow() {
    const sdk = new WildberriesSDK({
      apiKey: process.env.WB_API_KEY!
    });

    try {
      // 1. Get new orders and their statuses
      console.log('Fetching order statuses...');
      const statuses = await sdk.ordersDBS.getStatusesBulk([123456, 234567, 345678]);

      const newOrders = statuses.orders
        .filter(o => o.supplierStatus === 'new')
        .map(o => o.orderId);

      if (newOrders.length === 0) {
        console.log('No new orders to process');
        return;
      }

      // 2. Confirm orders (move to assembly)
      console.log(`Confirming ${newOrders.length} orders...`);
      const confirmResult = await sdk.ordersDBS.confirmBulk(newOrders);

      const confirmed = confirmResult.results
        .filter(r => !r.isError)
        .map(r => r.orderId);

      console.log(`Confirmed: ${confirmed.length}/${newOrders.length}`);

      // 3. After assembly, move to delivery
      console.log('Moving to delivery...');
      const deliverResult = await sdk.ordersDBS.deliverBulk(confirmed);

      // 4. After delivery, mark as received (with customer codes)
      const ordersWithCodes = [
        { orderId: 123456, code: '741852' },
        { orderId: 234567, code: '963258' }
      ];

      console.log('Marking as received...');
      const receiveResult = await sdk.ordersDBS.receiveBulk(ordersWithCodes);

      // Check results
      receiveResult.results.forEach(r => {
        if (r.isError) {
          console.error(`Order ${r.orderId} failed:`, r.errors);
        } else {
          console.log(`Order ${r.orderId} completed successfully`);
        }
      });

    } catch (error) {
      console.error('Error in DBS workflow:', error.message);
    }
  }

  dbsStatusWorkflow();
  ```

### Rate Limit Considerations

**Read Operations (300 req/min)**:
- `getStatusesBulk`, `getStatuses` (deprecated)
- 200ms interval between requests
- 20 burst limit

**Write Operations (100 req/min)**:
- All bulk status change methods
- 600ms interval between requests
- 20 burst limit
- **IMPORTANT**: 409 response counts as 10 requests!

### Status Transition Rules

```
Valid Transitions:
- new -> confirm (confirmBulk)
- confirm -> deliver (deliverBulk)
- deliver -> receive (receiveBulk, requires code)
- deliver -> reject (rejectBulk, requires code)
- new/confirm/deliver -> cancel (cancelBulk)

Invalid Transitions (will return 409):
- new -> deliver (must confirm first)
- new -> receive/reject (must confirm and deliver first)
- receive/reject/cancel -> any (final states)
```

### Confirmation Code Handling

For `receive` and `reject` operations, a confirmation code is required:
- Code is displayed to customer in WB app/website
- Seller must obtain code from customer
- Code validates that customer acknowledges delivery/rejection
