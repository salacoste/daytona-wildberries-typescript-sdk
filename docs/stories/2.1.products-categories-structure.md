### API Specifications

**Base URL**: `https://content-api.wildberries.ru`
[Source: OpenAPI spec wildberries_api_doc/02-products.yaml]

**Endpoints for Story 2.1**:

1. **GET /content/v2/object/parent/all** - Parent Categories
   - Returns parent categories (e.g., Electronics, Household chemicals)
   - Query params: `locale?: 'ru' | 'en' | 'zh'`
   - Response: `{ data: Array<{id: number, name: string, isVisible: boolean}>, error: boolean, errorText: string }`
   - Rate limit: 100 req/min, 600ms interval, 5 burst

2. **GET /content/v2/object/all** - Categories/Subjects
   - Returns hierarchical categories/subjects list
   - Query params: `locale?: string, name?: string, limit?: number (max 1000, default 30), offset?: number, parentID?: number`
   - Response: `{ data: Array<{subjectID: number, subjectName: string, parentID: number, parentName: string}> }`
   - Rate limit: 100 req/min, 600ms interval, 5 burst

3. **GET /content/v2/object/charcs/{subjectId}** - Characteristics
   - Returns characteristic definitions for a subject/category
   - Path param: `subjectId: number` (required)
   - Query params: `locale?: 'ru' | 'en' | 'zh'`
   - Response: `{ data: Array<{charcID: number, name: string, required: boolean, unitName: string, maxCount: number, charcType: number}> }`
   - Rate limit: 100 req/min, 600ms interval, 5 burst

**Authentication**: Bearer token via `Authorization` header (handled by BaseClient)
[Source: OpenAPI spec - security scheme HeaderApiKey]

### Data Models

**Primary Models** (to be generated in `src/types/products.types.ts`):

```typescript
// Parent Category Response
interface ParentCategoryResponse {
  data: ParentCategory[];
  error: boolean;
  errorText: string;
  additionalErrors: string | null;
}

interface ParentCategory {
  id: number;           // Parent category ID
  name: string;         // Category name (e.g., "Электроника")
  isVisible: boolean;   // Visible on website
}

// Category/Subject Response
interface CategoryResponse {
  data: Category[];
}

interface Category {
  subjectID: number;    // Subject/category ID
  subjectName: string;  // Subject name (e.g., "Носки")
  parentID: number;     // Parent category ID
  parentName: string;   // Parent category name
}

// Characteristics Response
interface CharacteristicsResponse {
  data: Characteristic[];
}

interface Characteristic {
  charcID: number;              // Characteristic ID
  subjectName: string;          // Subject name
  subjectID: number;            // Subject ID
  name: string;                 // Characteristic name
  required: boolean;            // Is required in product card
  unitName: string;             // Unit of measurement
  maxCount: number;             // Max values count
  charcType: number;            // Data type (0=not used, 1=string array, 2=number, 4=boolean, etc.)
}

// Query Filters
interface CategoryFilters {
  locale?: 'ru' | 'en' | 'zh';
  name?: string;                // Search by name (substring match)
  limit?: number;               // Max 1000, default 30
  offset?: number;              // Pagination offset
  parentID?: number;            // Filter by parent category
}
```

### Rate Limiting Configuration

**Products Content API Global Limit**:
- 100 requests per minute
- 600 millisecond interval between requests
- Burst limit: 5 requests
- **Exceptions**: Product creation/update endpoints have stricter limits (not in this story)

**Implementation**:
- Use BaseClient's built-in RateLimiter via `rateLimitKey` option
- Each method passes unique rate limit key (e.g., 'products.getParentCategories')
- RateLimiter enforces token bucket algorithm automatically
- No manual rate limit handling needed in ProductsModule

[Source: OpenAPI spec - rate limit tables in endpoint descriptions]

### Technical Constraints

**TypeScript**:
- Strict mode required (`strict: true` in tsconfig.json)
- Zero `any` types except in controlled error handling
- All public methods must have JSDoc with @param, @returns, @throws, @example
- Generic type parameters for BaseClient methods ensure type safety

**Module Pattern**:
- ProductsModule receives BaseClient via constructor injection
- Delegate all HTTP calls to BaseClient - NO direct Axios usage
- BaseClient handles auth headers, timeouts, error transformation, retry logic automatically
- Module focuses purely on API method definitions and types

**Error Handling**:
- BaseClient automatically throws typed errors (AuthenticationError, RateLimitError, NetworkError, ValidationError)
- ProductsModule methods document error types in JSDoc @throws
- No try/catch in module methods - let errors propagate to consumer

**Performance**:
- Bundle size target: <100KB gzipped for full SDK
- SDK overhead target: <200ms per operation (excluding API response time)
- ProductsModule must not add significant bundle bloat
