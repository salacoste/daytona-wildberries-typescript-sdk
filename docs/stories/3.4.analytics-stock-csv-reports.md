## Story

**As a** marketplace seller,
**I want** to access historical stock data and export analytics to CSV,
**so that** I can analyze inventory trends and integrate with external BI tools.

## Acceptance Criteria

1. `createProductsGroup(data: TableGroupRequestSt)` method retrieves stock data grouped by products
2. `createNmReportDownload(data: SalesFunnelProductReq | SearchReportGroupReq | StocksReportReq)` method creates CSV report generation task
3. `getDownloadsFile(downloadId: string)` method retrieves generated CSV/ZIP file
4. Stock history includes stock changes, reasons (sale, return, adjustment), and timestamps
5. CSV reports support all analytics data types (sales, stock, performance)
6. Large CSV files handled via download URLs with expiration
7. Rate limits enforced for export operations (typically stricter)
8. Unit tests validate stock history and CSV export methods
9. Integration tests validate CSV generation and download workflow
10. Example code demonstrates exporting analytics for Excel/BI tool integration

### Module Architecture

**Stock History Pattern**:
- Time-series data showing stock level changes over time
- Each entry includes: timestamp, previous stock, new stock, change amount, reason
- Reasons: sale, return, adjustment, transfer, damaged, lost
- Use for inventory trend analysis and restock predictions
- Data typically aggregated daily (snapshot at midnight)

**Async CSV Export Pattern** (Similar to Story 3.2 Financial Reports):
- CSV generation is **asynchronous** (not instant for large datasets)
- `createNmReportDownload()` returns immediately with `downloadId` and PENDING status
- Developer must poll `getNmReportDownloads()` until status becomes 'SUCCESS'
- Completed reports provide download URL (typically pre-signed S3 URL)
- URLs expire after period (typically 24 hours, check OpenAPI spec)

**CSV Format Options**:
- **Delimiter**: Comma (standard), semicolon (European Excel), tab (TSV)
- **Headers**: Include column names in first row (default: true)
- **Encoding**: UTF-8 (standard), UTF-8 with BOM (Excel compatibility)
- Excel import tip: Use semicolon delimiter for European locales

**Large File Considerations**:
- CSV exports can be very large (1M+ rows for long date ranges)
- API returns download URL, not file content directly
- Include file size and row count in metadata
- Document memory considerations for processing large CSVs

### Rate Limiting

From OpenAPI spec descriptions, stock/export endpoints typically have:
- Stock history: ~10 requests per minute
- CSV export initiation: ~2 requests per minute (resource-intensive, stricter limit)
- CSV status check: ~10 requests per minute
- CSV download: No specific limit (pre-signed URL, direct to storage)

Extract actual limits from `11-analytics.yaml` description fields during code generation.

### Stock Analysis Patterns

**Inventory Trend Analysis**:
- Track stock levels over time to identify patterns
- Calculate stock velocity (units sold per day)
- Predict restock dates based on current velocity
- Identify slow-moving inventory

**Stock Change Attribution**:
- Sales: Normal product sales (most common)
- Returns: Customer returns increasing stock
- Adjustments: Manual corrections (inventory audits)
- Transfer: Movement between warehouses
- Damaged: Damaged goods removal
- Lost: Lost/stolen inventory write-offs

**CSV Export Use Cases**:
- Import to Excel for pivot tables and charts
- Feed to BI tools (Tableau, Power BI, Looker)
- Automated reporting systems
- Data warehouse ETL pipelines
