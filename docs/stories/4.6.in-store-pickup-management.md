**I want** to manage pickup order assembly tasks, verify customer identity, and handle product metadata through the SDK,
**so that** I can efficiently process customer pickups at my physical location.

---

## Context

### Background

The In-Store Pickup module enables sellers to manage "click & collect" orders where customers purchase products online and pick them up at seller's physical location. This includes order assembly task management (new orders, confirmation, preparation, handover), customer identity verification, and product metadata management (SGTIN, UIN, IMEI, GTIN codes for regulated products).

**Key Operations**:
- **Order Assembly Management**: Process new pickup orders through lifecycle stages (new → confirm → prepare → receive/reject)
- **Customer Interaction**: Search for customer orders, verify customer identity at pickup
- **Order Status Tracking**: Monitor order statuses, list orders with filters
- **Metadata Management**: Manage product identification codes (SGTIN, UIN, IMEI, GTIN) for regulated products

### Technical Context

**API Documentation**: `wildberries_api_doc/06-in-store-pickup.yaml`

**Base URLs** (from Swagger):

**Key OpenAPI Paths** (to be verified from Swagger):
```yaml
# Order Assembly Tasks
/api/v3/click-collect/orders/new - Get new pickup orders

/api/v3/click-collect/orders/{orderId}/reject - Reject order

# Customer Interaction

/api/v3/click-collect/orders/client/identity - Verify customer identity (POST)

# Metadata Management
/api/v3/click-collect/orders/{orderId}/meta - Get/delete order metadata
/api/v3/click-collect/orders/{orderId}/meta/sgtin - Set SGTIN code (PUT)
/api/v3/click-collect/orders/{orderId}/meta/uin - Set UIN code (PUT)
/api/v3/click-collect/orders/{orderId}/meta/imei - Set IMEI code (PUT)
/api/v3/click-collect/orders/{orderId}/meta/gtin - Set GTIN code (PUT)
```

- Special note: **409 responses count as 5 requests** (conflict/state errors)
- Confirm/prepare operations: 100 req/min (600ms intervals, 20 burst) - from swagger example

### Order Lifecycle

**State Machine** (to be verified from Swagger):
```
NEW → CONFIRMED (via confirmOrder)
CONFIRMED → PREPARED (via prepareOrder)
PREPARED → RECEIVED (via receiveOrder) - terminal state
PREPARED → REJECTED (via rejectOrder) - terminal state
Any → CANCELLED (via cancelOrder) - terminal state
```

**Invalid Transitions**:
- Cannot confirm an already confirmed order
- Cannot prepare an unprepared order
- Cannot receive an order that's not prepared
- Throw `InvalidOrderStateError` (409) for invalid transitions

### Rate Limit Considerations

**From Swagger Analysis** (to be verified in Task 1):
- Assembly task operations: **300 requests per minute** (200ms intervals, 20 burst) - very generous!
- Confirm/prepare operations: 100 req/min (600ms intervals, 20 burst)
- **Special handling**: **409 responses count as 5 requests** toward rate limit

**Implementation**:
```typescript
// Track 409 responses as 5x penalty
catch (error) {
  if (error.response?.status === 409) {
    // Consume 4 additional tokens (already consumed 1)
    this.rateLimiter.consumeTokens('inStorePickup', 4);
    throw new InvalidOrderStateError(...);
  }
}
```

### Customer Verification

**Verification Process**:
1. Customer arrives at pickup location
2. Search customer orders by phone number
3. Verify customer identity using document
4. Complete order handover if verification succeeds

**Document Types** (to be verified from Swagger):
- Passport
- Driver's license
- National ID
- Other identification documents

### Metadata Management

**Identification Code Types**:
- **SGTIN** (Serialized Global Trade Item Number): Product tracking
- **UIN** (Unique Identification Number): Russian regulatory requirement
- **IMEI** (International Mobile Equipment Identity): Electronics (phones, tablets)
- **GTIN** (Global Trade Item Number): Product identification

**When Required**:
- Regulated products (pharmaceuticals, electronics, etc.)
- Products requiring traceability
- Electronics with IMEI codes
