## Story

**As a** SDK user,
**I want** automatic rate limit enforcement per endpoint,
**so that** my application never exceeds API limits and risks getting banned.

## Acceptance Criteria

1. `RateLimiter` class implements token bucket algorithm for request throttling
2. Rate limit configuration stored per endpoint key (e.g., `products.create`, `orders.list`)
3. `waitForSlot(key: string)` method queues requests and resolves when slot available
4. Supports configuration: requests per minute, interval seconds, burst limit
5. Multiple concurrent requests properly queued and released at correct intervals
6. Rate limit state maintained in-memory with no external dependencies
7. BaseClient integration: rate limiting applied before HTTP request execution
8. Unit tests validate token bucket logic with various limit configurations
9. Integration tests validate multi-request queueing and timing accuracy

### Architecture Overview

**Rate Limiting Strategy:** Token Bucket Algorithm

**Why Token Bucket?**
- Handles burst limits naturally (initial token capacity)
- Aligns with Wildberries API rate limit format (requests per minute + interval)
- Simple to implement with in-memory state
- O(1) time complexity per request

**Architecture Flow:**
```
API Module (e.g., ProductsModule)
         ↓
    BaseClient.post(url, data, { rateLimitKey: 'products.create' })
         ↓
    RateLimiter.waitForSlot('products.create')
         ↓ (if tokens available)
    Consume token, proceed immediately
         ↓ (if no tokens)
    Queue request, wait for token refill
         ↓ (token becomes available)
    Resolve queued Promise
         ↓
    HTTP request proceeds
```

### Token Bucket Algorithm Explanation

**Concept:** Each endpoint has a "bucket" of tokens. Making a request consumes 1 token. Tokens refill over time at a steady rate.

**Key Properties:**
- **Capacity (Burst Limit):** Maximum tokens the bucket can hold
- **Refill Rate:** Tokens added per unit time (e.g., 10 tokens/minute = 0.166 tokens/second)
- **Current Tokens:** Available tokens right now
- **Queue:** Requests waiting for tokens

**Example:**
```
Config: { requestsPerMinute: 6, intervalSeconds: 10, burstLimit: 6 }

Refill rate: 6 tokens / 60 seconds = 0.1 tokens/second

Timeline:
t=0s:  Make request → 6 tokens → consume 1 → 5 tokens remain
t=1s:  Make request → 5 tokens → consume 1 → 4 tokens remain
t=2s:  Make request → 4 tokens → consume 1 → 3 tokens remain
...
t=6s:  Make request → 0 tokens → QUEUE REQUEST
t=16s: Refill → 0 + (10s * 0.1) = 1 token → release queued request
```

**Burst Handling:**
If burstLimit=10 and requestsPerMinute=6, you can make 10 rapid requests initially, then limited to 1 req/10s.

### RateLimiter Class Implementation

**Location:** `src/client/rate-limiter.ts`

**Class Structure:**
```typescript
class TokenBucket {
  private tokens: number;
  private capacity: number;
  private refillRate: number;  // tokens per millisecond
  private lastRefill: number;  // timestamp
  private queue: Array<() => void>;

  constructor(config: RateLimitConfig) {
    this.capacity = config.burstLimit || config.requestsPerMinute;
    this.tokens = this.capacity;  // Start with full bucket
    this.refillRate = config.requestsPerMinute / 60000;  // per millisecond
    this.lastRefill = Date.now();
    this.queue = [];
  }

  refill(): void {
    const now = Date.now();
    const elapsed = now - this.lastRefill;
    const tokensToAdd = elapsed * this.refillRate;

    this.tokens = Math.min(this.capacity, this.tokens + tokensToAdd);
    this.lastRefill = now;
  }

  async consume(): Promise<void> {
    this.refill();

    if (this.tokens >= 1) {
      this.tokens -= 1;
      return; // Immediate execution
    }

    // Queue the request
    return new Promise<void>((resolve) => {
      this.queue.push(resolve);
      this.scheduleNextRelease();
    });
  }

  private scheduleNextRelease(): void {
    if (this.queue.length === 0) return;

    // Calculate when next token will be available
    const timeToNextToken = 1 / this.refillRate;

    setTimeout(() => {
      this.refill();
      if (this.tokens >= 1 && this.queue.length > 0) {
        this.tokens -= 1;
        const resolve = this.queue.shift()!;
        resolve();

        // Schedule next release if queue has more requests
        if (this.queue.length > 0) {
          this.scheduleNextRelease();
        }
      }
    }, timeToNextToken);
  }
}

export class RateLimiter {
  private buckets: Map<string, TokenBucket> = new Map();
  private config: EndpointLimits;

  constructor(config?: EndpointLimits) {
    this.config = config || {};
  }

  async waitForSlot(key: string): Promise<void> {
    const bucket = this.getOrCreateBucket(key);
    if (!bucket) return; // No rate limit configured

    await bucket.consume();
  }

  private getOrCreateBucket(key: string): TokenBucket | null {
    if (this.buckets.has(key)) {
      return this.buckets.get(key)!;
    }

    const config = this.config[key];
    if (!config) {
      return null; // No rate limit for this endpoint
    }

    const bucket = new TokenBucket(config);
    this.buckets.set(key, bucket);
    return bucket;
  }

  configure(key: string, config: RateLimitConfig): void {
    this.config[key] = config;
    // Reset bucket if it exists to apply new config
    this.buckets.delete(key);
  }

  canProceed(key: string): boolean {
    const bucket = this.buckets.get(key);
    if (!bucket) return true;
    bucket.refill();
    return bucket.tokens >= 1;
  }

  getRemainingTokens(key: string): number {
    const bucket = this.buckets.get(key);
    if (!bucket) return Infinity;
    bucket.refill();
    return bucket.tokens;
  }

  reset(key?: string): void {
    if (key) {
      this.buckets.delete(key);
    } else {
      this.buckets.clear();
    }
  }
}
```

export class BaseClient {

describe('RateLimiter', () => {
  beforeEach(() => {
    vi.useFakeTimers();

    const limiter = new RateLimiter({
      'test': { requestsPerMinute: 6, burstLimit: 6 }

    expect(elapsed).toBe(0); // Immediate

  });

  it('should queue request when no tokens available', async () => {
    const limiter = new RateLimiter({
      'test': { requestsPerMinute: 6, burstLimit: 1 }  // Burst of 1
    });

    // First request: immediate
    await limiter.waitForSlot('test');
    expect(limiter.getRemainingTokens('test')).toBe(0);

    // Second request: should queue
    const promise = limiter.waitForSlot('test');

    // Advance time to allow token refill (10 seconds for 1 token at 6/min rate)
    vi.advanceTimersByTime(10000);

    await promise; // Should resolve after token refill
    expect(limiter.getRemainingTokens('test')).toBe(0);
  });

  it('should process queued requests in FIFO order', async () => {
    const limiter = new RateLimiter({
      'test': { requestsPerMinute: 6, burstLimit: 1 }
    });

    const order: number[] = [];

    // Consume the only token
    await limiter.waitForSlot('test');

    // Queue 3 requests
    const p1 = limiter.waitForSlot('test').then(() => order.push(1));
    const p2 = limiter.waitForSlot('test').then(() => order.push(2));
    const p3 = limiter.waitForSlot('test').then(() => order.push(3));

    // Advance time to allow all tokens to refill
    vi.advanceTimersByTime(30000);

    await Promise.all([p1, p2, p3]);

    expect(order).toEqual([1, 2, 3]); // FIFO order
  });
});

### Performance Characteristics

**Time Complexity:**
- `waitForSlot()`: O(1) average case, O(n) worst case if many queued
- `refill()`: O(1)
- Memory: O(k) where k = number of unique endpoint keys

**Memory Management:**
- Each endpoint bucket: ~200 bytes
- Queue grows with concurrent requests (typically small)
- No memory leaks: setTimeout cleared when resolved

**Production Considerations:**
- Rate limiter state is in-memory (not persisted)
- Each SDK instance has independent rate limiting
- Multiple SDK instances (e.g., microservices) don't share state
- Consider distributed rate limiting for high-scale deployments (future enhancement)
