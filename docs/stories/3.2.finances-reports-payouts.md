## Story

**As a** marketplace seller,
**I want** to generate financial reports and track payouts,
**so that** I can analyze revenue trends and verify payments.

## Acceptance Criteria

1. `generateReport(reportType: FinancialReportType, dateRange: DateRange)` method creates financial report
2. `getReport(reportId: string)` method retrieves generated report (PDF/CSV/JSON)
3. `getPayouts(filters: PayoutFilters)` method retrieves payout history
4. `getPayoutById(payoutId: string)` method retrieves single payout details with breakdown
5. Report types include all supported formats from spec (sales summary, tax reports, commission breakdown)
6. Payout details include bank transfer information and fee breakdowns
7. Large reports properly handled with download URLs or streaming
8. Rate limits enforced for report generation operations
9. Unit tests validate report generation and payout retrieval
10. Integration tests validate complete reporting workflow
11. Example code demonstrates generating and downloading financial reports

### Module Architecture

**Async Report Generation Pattern**:
- Report generation is **asynchronous** (not instant)
- `generateReport()` returns immediately with `reportId` and status 'pending'
- Developer must poll `getReport(reportId)` until status becomes 'completed'
- Completed reports provide download URL (typically pre-signed S3 URL)
- URLs expire after time period (check OpenAPI spec for exact duration)

**Large File Handling**:
- Reports may be large (multi-MB PDFs, large CSV exports)
- API returns download URLs, not file content directly
- Consider streaming download pattern for very large files
- Document URL expiration behavior clearly

**Payout Fee Structure**:
- Payouts include multiple fee types: commission, processing fee, bank transfer fee
- Net amount = gross amount - total fees
- Fee breakdown provides transparency for reconciliation
- Bank account information masked for security (last 4 digits)

### Rate Limiting

From OpenAPI spec descriptions, report/payout endpoints typically have:
- Report generation: ~2 requests per minute (resource-intensive operation)
- Report status check: ~10 requests per minute
- Payout list: ~10 requests per minute
- Payout details: ~20 requests per minute

Extract actual limits from `13-finances.yaml` description fields during implementation.
