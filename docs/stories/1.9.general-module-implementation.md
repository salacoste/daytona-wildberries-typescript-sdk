### General Module Overview

**Purpose:** Utility module for connection testing, news retrieval, and seller information

**Endpoints (from 01-general.yaml):**

1. **GET /ping**
   - Purpose: Health check / connectivity test
   - Auth: Required (API key)
   - Response: `{ TS: string, Status: 'OK' }`
   - Use case: Validate API key and SDK setup

2. **GET /api/communications/v2/news**
   - Purpose: Retrieve Wildberries seller portal news
   - Auth: Required
   - Query params: `from?: string` (date), `fromID?: number`
   - Response: Array of news items
   - Use case: Keep sellers informed of platform changes

3. **GET /api/v1/seller-info**
   - Purpose: Get authenticated seller's account information
   - Auth: Required
   - Response: Seller profile data
   - Use case: Display seller details, validate account access

**Why General Module First?**

- Simple endpoints (all GET, minimal parameters)
- No complex business logic
- Perfect for validating infrastructure
- Useful for all SDK users (ping for health checks)
- Low risk of API changes

### Unit Testing Strategy

**Testing Approach:**

Unit tests focus on **module behavior in isolation** using mocked BaseClient. This tests the generated module code without hitting real infrastructure.

**Mock BaseClient Pattern:**

```typescript
const mockClient = {
  get: vi.fn(),
  post: vi.fn(),
  put: vi.fn(),
  patch: vi.fn(),
  delete: vi.fn()
} as unknown as BaseClient;
```

**Why Mock BaseClient?**

- Isolates module logic from HTTP infrastructure
- Fast tests (no network, no delays)
- Deterministic (no flaky tests from network issues)
- Tests module's delegation to BaseClient
- Validates method signatures and type safety

**Test Structure:**

```typescript
describe('GeneralModule', () => {
  let generalModule: GeneralModule;

  beforeEach(() => {
    generalModule = new GeneralModule(mockClient);
  });

  afterEach(() => {
    vi.clearAllMocks();
  });

  describe('ping()', () => {
    it('should call BaseClient.get with correct URL', async () => {
      mockClient.get.mockResolvedValue({ TS: '...', Status: 'OK' });

      await generalModule.ping();

      expect(mockClient.get).toHaveBeenCalledWith(
        'https://common-api.wildberries.ru/ping'
      );
    });

    it('should return typed response', async () => {
      const mockResponse = { TS: '2024-01-01T00:00:00Z', Status: 'OK' };
      mockClient.get.mockResolvedValue(mockResponse);

      const result = await generalModule.ping();

      expect(result).toEqual(mockResponse);
      expect(result.Status).toBe('OK'); // Type-safe access
    });
  });
});
```

### Integration Testing Strategy with MSW

**Testing Approach:**

Integration tests use **real infrastructure** (BaseClient, RateLimiter, RetryHandler) with **mocked HTTP** (MSW). This validates the complete request flow without hitting real APIs.

**MSW (Mock Service Worker):**

MSW intercepts HTTP requests at the network level (fetch/Axios) and returns mocked responses. This provides realistic integration testing.

**Setup Pattern:**

```typescript
import { setupServer } from 'msw/node';
import { http, HttpResponse } from 'msw';

const server = setupServer(
  http.get('https://common-api.wildberries.ru/ping', () => {
    return HttpResponse.json({
      TS: new Date().toISOString(),
      Status: 'OK'
    });
  })
);

beforeAll(() => server.listen());
afterEach(() => server.resetHandlers());
afterAll(() => server.close());
```

**What Integration Tests Validate:**

1. **Complete Request Flow:**
   - GeneralModule → BaseClient → RateLimiter → RetryHandler → Axios → MSW
   - All components working together

2. **Rate Limiting:**
   - Multiple requests queued correctly
   - Rate limits enforced per endpoint
   - Timing accurate

3. **Retry Logic:**
   - Transient failures retried
   - Permanent failures not retried
   - Exponential backoff timing

4. **Error Transformation:**
   - HTTP 401 → AuthenticationError
   - HTTP 429 → RateLimitError
   - HTTP 500 → NetworkError (with retry)

5. **End-to-End Flows:**
   - Real SDK initialization
   - Real method calls
   - Real error handling

**Example Integration Test:**

```typescript
describe('GeneralModule Integration', () => {
  it('should handle complete ping flow', async () => {
    const sdk = new WildberriesSDK({ apiKey: 'test-key' });

    const result = await sdk.general.ping();

    expect(result.Status).toBe('OK');
    expect(result.TS).toBeDefined();
  });

  it('should retry on transient failure', async () => {
    let attempts = 0;

    server.use(
      http.get('https://common-api.wildberries.ru/ping', () => {
        attempts++;
        if (attempts < 3) {
          return new HttpResponse(null, { status: 503 });
        }
        return HttpResponse.json({ TS: '...', Status: 'OK' });
      })
    );

    const sdk = new WildberriesSDK({ apiKey: 'test-key' });
    const result = await sdk.general.ping();

    expect(attempts).toBe(3); // Retried twice
    expect(result.Status).toBe('OK');
  });
});
```

### Error Handling Validation

**Error Types to Test:**

1. **AuthenticationError (401/403)**
   - Invalid API key
   - Expired token
   - No retry (permanent failure)
   - User-friendly message

2. **RateLimitError (429)**
   - Rate limit exceeded
   - Includes `retryAfter` property
   - Can be retried
   - SDK retries automatically

3. **ValidationError (400/422)**
   - Invalid request data
   - Field-level errors
   - No retry (permanent failure)

4. **NetworkError (5xx, timeout, network failure)**
   - Transient failures
   - Automatically retried
   - Final error if retries exhausted

**Test Pattern:**

```typescript
it('should transform 401 to AuthenticationError', async () => {
  server.use(
    http.get('https://common-api.wildberries.ru/ping', () => {
      return new HttpResponse(null, {
        status: 401,
        statusText: 'Unauthorized'
      });
    })
  );

  const sdk = new WildberriesSDK({ apiKey: 'invalid-key' });

  await expect(sdk.general.ping()).rejects.toThrow(AuthenticationError);
  await expect(sdk.general.ping()).rejects.toThrow('Invalid API key');
});
```

2. **Rate Limiting Enforced:**

**Test Pattern:**

```typescript
it('should enforce rate limits', async () => {
  // Configure strict limit for testing
  const sdk = new WildberriesSDK({
    apiKey: 'test-key',
    rateLimitConfig: {
      requestsPerMinute: 6, // 1 req every 10s
      intervalSeconds: 10
    }
  });

  const startTime = Date.now();

  // Make 3 rapid requests
  const promises = [
    sdk.general.ping(),
    sdk.general.ping(),
    sdk.general.ping()
  ];

  await Promise.all(promises);

  const elapsed = Date.now() - startTime;

  // Should take ~20 seconds (0s, 10s, 20s)
  expect(elapsed).toBeGreaterThan(20000);
  expect(elapsed).toBeLessThan(22000);
}, 30000); // 30s timeout
```

### Retry Logic Validation

**What to Validate:**

1. **Transient Failures Retried:**
   - 5xx errors → retry
   - Network timeouts → retry
   - Network failures → retry

2. **Permanent Failures Not Retried:**
   - 4xx errors (except 429) → no retry
   - AuthenticationError → no retry

3. **Exponential Backoff:**
   - Delay increases: 1s, 2s, 4s
   - Jitter adds randomness (±10%)
   - Max delay capped at 30s

4. **Retry Exhaustion:**
   - After max retries, throw final error
   - Error not wrapped

**Test Pattern:**

```typescript
it('should retry on 503 and eventually succeed', async () => {
  let attempts = 0;

  server.use(
    http.get('https://common-api.wildberries.ru/ping', () => {
      attempts++;
      if (attempts < 3) {
        return new HttpResponse(null, { status: 503 });
      }
      return HttpResponse.json({ TS: '...', Status: 'OK' });
    })
  );

  const sdk = new WildberriesSDK({ apiKey: 'test-key' });
  const result = await sdk.general.ping();

  expect(attempts).toBe(3);
  expect(result.Status).toBe('OK');
});

it('should not retry on 400 validation error', async () => {
  let attempts = 0;

  server.use(
    http.get('https://common-api.wildberries.ru/ping', () => {
      attempts++;
      return new HttpResponse(null, { status: 400 });
    })
  );

  const sdk = new WildberriesSDK({ apiKey: 'test-key' });

  await expect(sdk.general.ping()).rejects.toThrow();
  expect(attempts).toBe(1); // No retry
});
```

### Example Usage Pattern

**Purpose of examples/general.ts:**

- Show developers how to use the SDK
- Demonstrate error handling
- Provide copy-paste starter code
- Validate SDK is usable

**Example Structure:**

```typescript
import { WildberriesSDK } from '../src';
import { AuthenticationError, RateLimitError } from '../src/errors';

async function main() {
  // 1. Initialize SDK
  const sdk = new WildberriesSDK({
    apiKey: process.env.WB_API_KEY || 'your-api-key'
  });

  // 2. Simple usage - ping
  try {
    const ping = await sdk.general.ping();
    console.log('✓ Connection successful:', ping.Status);
  } catch (error) {
    console.error('✗ Connection failed:', error.message);
    return;
  }

  // 3. With parameters - get news
  try {
    const news = await sdk.general.getNews({
      from: '2024-01-01'
    });
    console.log(`Found ${news.data.length} news items`);
    news.data.forEach(item => {
      console.log(`- ${item.header}: ${item.content.substring(0, 50)}...`);
    });
  } catch (error) {
    if (error instanceof RateLimitError) {
      console.error(`Rate limited. Retry after ${error.retryAfter}ms`);
    } else {
      console.error('Error fetching news:', error.message);
    }
  }

  // 4. Error handling - seller info
  try {
    const seller = await sdk.general.getSellerInfo();
    console.log('Seller:', seller);
  } catch (error) {
    if (error instanceof AuthenticationError) {
      console.error('Invalid API key. Get one from https://seller.wildberries.ru/');
    } else {
      console.error('Error:', error.message);
    }
  }
}

main().catch(console.error);
```

### Troubleshooting

**Common Issues:**

1. **Generated code doesn't compile:**
   - Check generators (Stories 1.6-1.8) work correctly
   - Verify OpenAPI spec is valid
   - Re-run generator: `npm run generate`

2. **Unit tests fail:**
   - Check mock setup correct
   - Verify expectations match generated code
   - Ensure mocks reset between tests

3. **Integration tests fail:**
   - Check MSW handlers match actual URLs
   - Verify MSW server lifecycle (listen, reset, close)
   - Check for timing issues (use longer timeouts)

4. **Rate limit tests flaky:**
   - Timing tests are sensitive
   - Use reasonable tolerance ranges
   - Consider using vi.useFakeTimers

5. **Example doesn't work:**
   - Check API key set correctly
   - Verify imports resolve
   - Check for TypeScript compilation errors
