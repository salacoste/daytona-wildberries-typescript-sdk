# Epic 8: Code Generator Syntax & Validation Fixes

## Epic Overview

**Priority:** HIGH
**Discovered:** 2025-12-15
**Status:** To Do

---

## Description

**Problem:** The SDK code generator (`tools/generate-sdk.ts`) produces invalid TypeScript code in several scenarios, preventing the SDK from being imported and used. These issues were discovered during storage fees API verification testing.

**Impact:**
- SDK cannot be compiled due to syntax errors
- Backend teams cannot use SDK methods directly
- Integration tests fail to execute
- Developer experience severely degraded

**Root Cause:** Generator does not validate output TypeScript syntax before writing files.

---

## Issues Discovered

### Issue 1: Invalid Interface Names Starting with Numbers

**Severity:** CRITICAL
**Files Affected:**
- `src/types/promotion.types.ts:10` → `export interface 400Response`
- `src/types/reports.types.ts:470` → `export interface 4xxResponse`

**Error:**
```
ERROR: Expected identifier but found "4"
ERROR: Syntax error "R"
```

**Root Cause:** Generator takes schema names from OpenAPI verbatim without validating TypeScript identifier rules.

**OpenAPI Source:**
```yaml
components:
  schemas:
    400Response:
      type: object
      properties:
        error:
          type: string
```

**Current Output (Invalid):**
```typescript
export interface 400Response {
  error?: string;
}
```

**Expected Output (Valid):**
```typescript
export interface Response400 {
  error?: string;
}
```

---

### Issue 2: Corrupted Import Statements with Inline Types

**Severity:** CRITICAL
**Files Affected:**
- `src/modules/reports/index.ts:8`

**Error:**
```
ERROR: Expected identifier but found "1"
```

**Current Output (Invalid):**
```typescript
import type { 1; nmId: number; orderDt: string; orderId: number; ... } }, CreateTaskResponse, ... } from '../../types/reports.types';
```

**Expected Output (Valid):**
```typescript
import type { CreateTaskResponse, ExciseReportRequest, ... } from '../../types/reports.types';
```

**Root Cause:** Generator inserts inline type definitions instead of referencing interface names.

---

### Issue 3: Invalid Object Keys with Dashes

**Severity:** HIGH
**Files Affected:**
- `src/config/orders-fbs-rate-limits.ts:16`

**Error:**
```
ERROR: Expected ";" but found "-"
```

**Root Cause:** Generator creates object keys with dashes without quoting them.

**Current Output (Invalid):**
```typescript
const rateLimits = {
  orders-fbs-create: { ... }
};
```

**Expected Output (Valid):**
```typescript
const rateLimits = {
  'orders-fbs-create': { ... }
};
```

## Technical Implementation Plan

### Phase 1: Type Name Sanitization

**File:** `tools/generators/type-mapper.ts`

```typescript
/**
 * Sanitize schema name to valid TypeScript identifier
 * - Names cannot start with numbers
 * - Names can only contain alphanumeric and underscore
 */
export function sanitizeTypeName(name: string): string {
  // If starts with number, prefix with appropriate word
  if (/^\d/.test(name)) {
    // Detect common patterns
    if (/^\d{3}Response$/i.test(name)) {
      return `Response${name.replace('Response', '')}`; // 400Response → Response400
    }
    if (/^\dxx/i.test(name)) {
      return `Response${name}`; // 4xxResponse → Response4xx
    }
    return `Type${name}`;
  }

  // Replace invalid characters
  return name.replace(/[^a-zA-Z0-9_]/g, '_');
}
```

**Integration Points:**
- `generateTypeScriptInterface()` in schema-to-interface.ts
- `toPascalCase()` in type-mapper.ts
- All places where schema names become TypeScript identifiers

### Phase 2: Import Statement Validation

**File:** `tools/generators/method-generator.ts`

```typescript
/**
 * Generate import statement with only valid type references
 */
function generateImportStatement(types: string[], typesFile: string): string {
  // Filter to only valid TypeScript identifiers
  const validTypes = types.filter(t => /^[a-zA-Z_][a-zA-Z0-9_]*$/.test(t));

  if (validTypes.length === 0) {
    return ''; // No types to import
  }

  return `import type { ${validTypes.join(', ')} } from '${typesFile}';`;
}
```

**Additional Validation:**
- Parse generated types file to extract actual exported interfaces
- Cross-reference imports against available exports
- Error if import references non-existent type

### Phase 3: Object Key Sanitization

**File:** `tools/generators/rate-limit-generator.ts`

```typescript
/**
 * Sanitize object key for JavaScript/TypeScript
 */
export function sanitizeObjectKey(key: string): string {
  // If key contains special characters, quote it
  if (/[^a-zA-Z0-9_$]/.test(key)) {
    return `'${key}'`;
  }
  return key;
}

// Usage in rate limit generation
const configEntry = `${sanitizeObjectKey(endpointKey)}: { ... }`;
```

### Phase 4: Output Validation Step

**File:** `tools/generate-sdk.ts`

```typescript
import { execSync } from 'child_process';

async function validateGeneratedCode(): Promise<void> {
  console.log('Validating generated TypeScript...');

  try {
    // Run TypeScript compiler in check mode
    execSync('npx tsc --noEmit', {
      cwd: process.cwd(),
      stdio: 'pipe'
    });
    console.log('✅ Generated code compiles successfully');
  } catch (error) {
    console.error('❌ Generated code has TypeScript errors:');
    console.error(error.stdout?.toString() || error.message);
    process.exit(1);
  }
}

// Call at end of generation
await generateAllModules();
await validateGeneratedCode();
```
