## Bug Fixed

### getStatsKeywords URL Error

**Issue**: SSL certificate error when calling `getStatsKeywords()`

**Error Message**:
```
ERR_TLS_CERT_ALTNAME_INVALID: Host: api.wildberries.ru
```

**Root Cause**: Incorrect base URL in `src/modules/promotion/index.ts:712`

**Fix Applied**:
```typescript
// Before (line 712):
return this.client.get<V0KeywordsStatisticsResponse>(
  'https://api.wildberries.ru/adv/v0/stats/keywords',
  { params: options }
);

// After (fixed):
return this.client.get<V0KeywordsStatisticsResponse>(
  'https://advert-api.wildberries.ru/adv/v0/stats/keywords',
  { params: options }
);
```

**Verification**: Method now works correctly with active campaigns.

## ⚠️ CRITICAL: Getting Campaign Details by Type

### The Problem

Wildberries API uses **different endpoints** for different campaign types:

- **`getAuctionAdverts()`** works ONLY for **type 9** campaigns
- **`createPromotionAdvert()`** works ONLY for **types 4-8** (legacy) campaigns
- There is **NO universal method** to get details for all campaign types

### API Methods by Campaign Type

| SDK Method | API Endpoint | Campaign Types | Description |
|------------|--------------|----------------|-------------|
| `getPromotionCount()` | `GET /adv/v1/promotion/count` | **ALL** (4-9) | List all campaigns with IDs |
| `createPromotionAdvert()` | `POST /adv/v1/promotion/adverts` | **4-8** only | Get details for LEGACY campaigns |
| `getAuctionAdverts()` | `GET /adv/v0/auction/adverts` | **9** only | Get details for MODERN campaigns |

### ⚠️ Naming Confusion

**`createPromotionAdvert()`** - The name is MISLEADING!
- It does NOT create campaigns
- It GETS information about legacy campaigns (types 4-8)
- Better name would be: `getLegacyCampaignDetails()` or `getPromotionAdverts()`

### Correct Workflow to Get All Campaign Details

```typescript
import { WildberriesSDK } from 'daytona-wildberries-typescript-sdk';

const sdk = new WildberriesSDK({ apiKey: process.env.WB_API_KEY! });

async function getAllCampaignDetails() {
  // Step 1: Get list of ALL campaigns
  const allCampaigns = await sdk.promotion.getPromotionCount();

  // Step 2: Separate by type
  const type9Ids: number[] = [];
  const legacyIds: number[] = [];

  allCampaigns.adverts?.forEach(group => {
    group.advert_list?.forEach(advert => {
      if (group.type === 9) {
        type9Ids.push(advert.advertId!);
      } else if (group.type && group.type >= 4 && group.type <= 8) {
        legacyIds.push(advert.advertId!);
      }
    });
  });

  console.log(`Found ${type9Ids.length} type 9 campaigns`);
  console.log(`Found ${legacyIds.length} legacy campaigns (types 4-8)`);

  // Step 3: Get details for type 9 campaigns (MODERN)
  if (type9Ids.length > 0) {
    const type9Details = await sdk.promotion.getAuctionAdverts({
      ids: type9Ids.slice(0, 50).join(',')  // Max 50 IDs per request
    });
    console.log('Type 9 campaign details:', type9Details);
  }

  // Step 4: Get details for legacy campaigns (types 4-8)
  if (legacyIds.length > 0) {
    const legacyDetails = await sdk.promotion.createPromotionAdvert(
      legacyIds.slice(0, 50)  // Max 50 IDs per request
    );
    console.log('Legacy campaign details:', legacyDetails);
  }
}
```

### Why Two Methods?

From Wildberries API documentation (08-promotion.yaml, line 131-133):

```yaml
description: |
  Метод возвращает информацию о рекламных кампаниях с устаревшими типами (4-8)
  Для получения информации о кампаниях с типом 9 используйте отдельный метод
```

Translation: "This method returns information about campaigns with deprecated types (4-8). To get information about type 9 campaigns, use a separate method."

### Response Differences

**Type 9 (getAuctionAdverts)** returns:
```typescript
{
  adverts: {
    id: number;
    status: number;
    bid_type: 'manual' | 'unified';  // Important!
    settings: { name, payment_type, placements };
    nm_settings: [{ nm_id, bids, subject }];
    timestamps: { created, started, updated, deleted };
  }
}
```

**Types 4-8 (createPromotionAdvert)** returns:
```typescript
{
  advertId: number;
  type: number;  // 4-8
  status: number;
  name: string;
  createTime: string;
  changeTime: string;
  // Structure varies by type
}
```

## Recommendations

### For SDK Users

1. **Use correct method names** - Generated from Swagger (e.g., `getAdvStart()` not `startAdvert()`)
2. **Respect status requirements** - Check campaign status before operations
3. **Implement delays** - 5 seconds between most calls
4. **Handle errors** - Use try/catch with typed errors

### For SDK Development

1. **Consider method aliases** - Add intuitive aliases like `startCampaign()` → `getAdvStart()`
2. **Add status validation** - Validate campaign status before state-changing operations
3. **Document requirements** - Include status requirements in JSDoc
