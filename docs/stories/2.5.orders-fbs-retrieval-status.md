## Story

**As a** marketplace seller using FBS (Fulfillment by Seller),
**I want** to retrieve orders and update their status,
**so that** I can process orders from my own warehouse.

## Acceptance Criteria

1. Orders FBS module generated from `03-orders-fbs.yaml` with type definitions
2. `getNewOrders()` method retrieves all new orders awaiting processing
3. `getOrders(filters: OrderFilters)` method retrieves orders with date range, pagination
4. `getOrderStatuses(orderIds: number[])` method retrieves current status for multiple orders
5. OrderStatus enums include all valid states: `supplierStatus` (new, confirm, complete, cancel) and `wbStatus` (waiting, sorted, sold, canceled, etc.)
6. Order filters support date ranges (Unix timestamps), pagination (limit/next pattern)
7. Rate limits enforced per endpoint (300 req/min, 200ms interval)
8. Error handling for invalid status transitions with meaningful messages
9. Unit tests validate all order retrieval and status methods
10. Integration tests validate order filtering and status retrieval flows
11. Example code demonstrates order processing workflow (fetch new → check status)

      console.log('=== FBS Order Processing Workflow ===\n');

      console.log('Step 1: Fetching new FBS orders...');
      const newOrders = await sdk.ordersFBS.getNewOrders();

        console.log(`  Delivery Address: ${firstOrder.address?.fullAddress || 'Pickup'}\n`);

      console.log('Step 2: Fetching orders from last 7 days...');
      const sevenDaysAgo = Math.floor(Date.now() / 1000) - (7 * 24 * 60 * 60);
      const now = Math.floor(Date.now() / 1000);

      let allOrders: Order[] = [];

      do {

        console.log(`  Page ${pageCount}: ${response.orders.length} orders`);

      // 3. Check statuses for specific orders
      if (allOrders.length > 0) {

        // Get statuses for first 5 orders
        const orderIds = allOrders.slice(0, 5).map(o => o.id);
        const statuses = await sdk.ordersFBS.getOrderStatuses(orderIds);

        console.log(`Checked ${statuses.length} order statuses:\n`);

        statuses.forEach(status => {
          console.log(`  Order ${status.id}:`);
          console.log(`    Supplier Status: ${status.supplierStatus}`);
          console.log(`    WB Status: ${status.wbStatus}`);
        });
      }

      // 4. Status breakdown
      console.log('\nStep 4: Order status breakdown...');
      if (allOrders.length > 0) {
        const orderIds = allOrders.map(o => o.id);
        const statuses = await sdk.ordersFBS.getOrderStatuses(orderIds);

        const statusBreakdown = statuses.reduce((acc, status) => {
          acc[status.supplierStatus] = (acc[status.supplierStatus] || 0) + 1;
          return acc;
        }, {} as Record<string, number>);

        console.log('By Supplier Status:');
        Object.entries(statusBreakdown).forEach(([status, count]) => {
          console.log(`  ${status}: ${count} orders`);
        });
      }

      console.log('\n✅ FBS order processing workflow completed');
    }

        console.error('❌ Error:', error.message);

          console.error('Invalid request parameters (check date range)');
        }
        if (error.statusCode === 429) {
          console.error('Rate limit exceeded - try again later');
        }
      });

### API Specifications

**Base URL**: `https://marketplace-api.wildberries.ru`
[Source: OpenAPI spec wildberries_api_doc/03-orders-fbs.yaml, lines 328, 369, 437]

**Orders FBS Endpoints**:

1. **GET /api/v3/orders/new** - Get New FBS Orders
   - **Purpose**: Retrieve all new assembly tasks (сборочные задания) awaiting processing
   - **Returns**: `{ orders: OrderNew[] }` - Array of new orders
   - **No filters**: Returns all new orders at request time
   - **Rate limit**: 300 req/min, 200ms interval, 20 burst
   [Source: Lines 326-366 in 03-orders-fbs.yaml]

2. **GET /api/v3/orders** - Get FBS Orders with Filters
   - **Query params**:
     - `limit` (required): 1-1000 orders per request
     - `next` (required): Pagination cursor, 0 for first page
     - `dateFrom` (optional): Unix timestamp, default 30 days ago
     - `dateTo` (optional): Unix timestamp, default now
   - **Returns**: `{ next: number, orders: Order[] }` - Orders + pagination cursor
   - **IMPORTANT**: Returns orders WITHOUT current status - use POST /api/v3/orders/status to get status
   - **Max date range**: 30 calendar days per request
   - **Pagination**: Continue while `next > 0`
   - **Rate limit**: 300 req/min, 200ms interval, 20 burst
   [Source: Lines 367-434 in 03-orders-fbs.yaml]

3. **POST /api/v3/orders/status** - Get Order Statuses
   - **Request body**: `{ orders: number[] }` - Array of order IDs (1-1000)
   - **Returns**: `{ orders: OrderStatus[] }` - Array with id, supplierStatus, wbStatus
   - **Two status types**:
     - `supplierStatus` - Seller-controlled: new, confirm, complete, cancel
     - `wbStatus` - WB system status: waiting, sorted, sold, canceled, etc.
   - **Rate limit**: 300 req/min, 200ms interval, 20 burst
   [Source: Lines 435-559 in 03-orders-fbs.yaml]

**Authentication**: Bearer token via `Authorization` header (handled by BaseClient)
[Source: OpenAPI spec - security scheme HeaderApiKey]

### Critical Implementation Notes

**1. FBS vs FBW Distinction** 📦

- **FBS (Fulfillment by Seller)**: This module. Seller processes orders from own warehouse, delivers to WB offices
- **FBW (Fulfillment by Wildberries)**: Story 2.7. WB handles logistics from WB warehouses
- Orders returned have `deliveryType: 'fbs'` for this module

[Source: Lines 2734-2741, 2980-2987 in 03-orders-fbs.yaml]

**2. Orders WITHOUT Current Status** ⚠️

GET /api/v3/orders returns order details but NOT current status. Must use POST /api/v3/orders/status separately to get status.

**Pattern**:
```typescript
// Get orders

// Get statuses separately
const orderIds = orders.orders.map(o => o.id);
const statuses = await sdk.ordersFBS.getOrderStatuses(orderIds);
```

[Source: Lines 377 in 03-orders-fbs.yaml - description]

**3. Two Status Types** 🔄

Orders have TWO status fields:

- **supplierStatus** (seller-controlled):
  - `new` → New assembly task
  - `confirm` → On assembly (when added to supply via Story 2.6)
  - `complete` → In delivery (when supply delivered via Story 2.6)
  - `cancel` → Canceled by seller (via Story 2.6)

- **wbStatus** (WB system):
  - `waiting`, `sorted`, `sold`, `canceled`, `canceled_by_client`, `declined_by_client`, `defect`, `ready_for_pickup`, `postponed_delivery`

**Status transitions** triggered by supply operations, not direct status updates.
