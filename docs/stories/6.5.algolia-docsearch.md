# Story 6.5: Algolia DocSearch Integration

## Status

Not Needed (Skipped)

## Story

**As a** SDK user,
**I want** full-text search across all documentation,
**so that** I can quickly find answers to specific questions without manual navigation.

## Acceptance Criteria

1. Algolia DocSearch account created and SDK project approved for free tier
2. Algolia credentials configured in VitePress config (appId, apiKey, indexName)
3. Search box appears in top navigation bar (Ctrl+K / Cmd+K shortcut)
4. Search indexes all documentation pages (Getting Started, Guides, API Reference, FAQ)
5. Search results display page title, description, and matched content snippet
6. Search supports keyboard navigation (arrow keys, Enter to select)
7. Algolia crawler configuration file created (docsearch.json) specifying selectors
8. Search tested with 10 common queries (e.g., "rate limiting", "authentication", "error handling")

- Guide topics return correct guide pages

**IV3: Performance Impact**

- Page load time remains <2s on 3G with search enabled

### Algolia DocSearch Overview

**What is Algolia DocSearch?**
- Free search service for open-source documentation
- Crawls documentation site and indexes content
- Provides instant search with typo tolerance
- Optimized for technical documentation

**Requirements for free tier:**
- Open-source project (public GitHub repo)
- Publicly accessible documentation
- Technical documentation (not marketing site)

**Approval process:**
- Submit application at https://docsearch.algolia.com/apply/
- Wait 1-3 business days for review
- Receive credentials via email
- Configure crawler and start indexing

[Source: Algolia DocSearch documentation]

### VitePress Algolia Configuration

**Configuration location:** `.vitepress/config.ts`

**Full configuration example:**
```typescript
import { defineConfig } from 'vitepress';

export default defineConfig({
  themeConfig: {
    search: {
      provider: 'algolia',
      options: {
        appId: process.env.ALGOLIA_APP_ID || '',
        apiKey: process.env.ALGOLIA_API_KEY || '',
        indexName: process.env.ALGOLIA_INDEX_NAME || 'wildberries-sdk',

        // Optional: Customize search behavior
        searchParameters: {
          facetFilters: ['language:en'] // Filter by language (for i18n)
        },

        // Optional: Customize search placeholder
        placeholder: 'Search documentation...',

        // Optional: Customize translations
        translations: {
          button: {
            buttonText: 'Search',
            buttonAriaLabel: 'Search documentation'
          },
          modal: {
            searchBox: {
              resetButtonTitle: 'Clear query',
              resetButtonAriaLabel: 'Clear query',
              cancelButtonText: 'Cancel',
              cancelButtonAriaLabel: 'Cancel'
            },
            footer: {
              selectText: 'to select',
              navigateText: 'to navigate',
              closeText: 'to close'
            }
          }
        }
      }
    }
  }
});
```

**Environment variable handling:**
- Use `process.env.ALGOLIA_*` for credentials
- Fallback to empty string if not set (graceful degradation)
- Never commit credentials to git

[Source: Context7 VitePress docs + Algolia DocSearch docs]

### Algolia Crawler Configuration

**Create `.algolia/docsearch.json`:**
```json
{
  "index_name": "wildberries-sdk",
  "start_urls": [
    {
      "url": "https://<username>.github.io/<repo>/",
      "selectors_key": "default"
    }
  ],
  "sitemap_urls": [
    "https://<username>.github.io/<repo>/sitemap.xml"
  ],
  "selectors": {
    "default": {
      "lvl0": {
        "selector": ".sidebar .active",
        "global": true,
        "default_value": "Documentation"
      },
      "lvl1": ".vp-doc h1",
      "lvl2": ".vp-doc h2",
      "lvl3": ".vp-doc h3",
      "lvl4": ".vp-doc h4",
      "lvl5": ".vp-doc h5",
      "text": ".vp-doc p, .vp-doc li, .vp-doc td"
    }
  },
  "selectors_exclude": [
    ".vp-doc .aside",
    ".vp-doc .footer"
  ],
  "stop_urls": [],
  "min_indexed_level": 1,
  "nb_hits": 10000
}
```

**Key configuration points:**
- `start_urls`: GitHub Pages URL (after Story 6.9 deployment)
- `sitemap_urls`: Auto-generated by VitePress
- `selectors`: Match VitePress HTML structure
- `.vp-doc`: VitePress content container class
- `lvl0-5`: Heading hierarchy for search results
- `text`: Paragraph and list content to index

**Update after deployment:**
- Replace `<username>` with actual GitHub username
- Replace `<repo>` with actual repository name
- Submit to Algolia via DocSearch dashboard

### Graceful Degradation Strategy

**If Algolia credentials missing:**
1. VitePress checks for `search.provider = 'algolia'`
2. If credentials empty, VitePress either:
   - Falls back to local search (built-in minisearch)
   - Or hides search component
3. Site continues to function without search

**Testing graceful degradation:**
```bash
# Temporarily remove credentials
unset ALGOLIA_APP_ID
unset ALGOLIA_API_KEY
unset ALGOLIA_INDEX_NAME

# Run dev server
npm run docs:dev

# Verify site works (search may be disabled or use fallback)
```

**Recommendation:** Configure local search as fallback in VitePress config for development.

### Common Issues and Solutions

**Issue 1: Algolia application not approved**
- Solution: Verify project is open-source, documentation is public
- Timeline: Reapply if rejected, typically 1-3 business days
- Fallback: Use VitePress local search temporarily

**Issue 2: Search returns no results**
- Solution: Verify crawler has run, check indexName matches config
- Debug: Check Algolia dashboard for index status
- Crawler typically runs daily, may need manual trigger

**Issue 3: Search modal doesn't open**
- Solution: Check JavaScript console for errors, verify credentials
- Validation: Test with browser DevTools open

**Issue 4: Search results irrelevant**
- Solution: Refine crawler selectors, exclude sidebar/footer
- Improvement: Adjust search parameters in VitePress config

**Issue 5: Performance impact on page load**
- Solution: Verify Algolia script loads async
- Validation: Check Network tab in DevTools, should not block render

[Source: Common Algolia DocSearch integration issues]

### Security Considerations

**API Key Security:**
- Use **search-only API key** (never admin key)
- Search-only key is safe to expose in client-side code
- Admin key should NEVER be committed or exposed

**Environment Variables:**
- Store credentials in GitHub Secrets for CI/CD
- Use `.env.local` for local development (gitignored)
- Never commit `.env` files with real credentials

**Crawler Access:**
- Crawler only accesses public documentation
- No authentication required
- No sensitive data indexed
