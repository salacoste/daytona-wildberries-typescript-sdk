1. `tools/generate-sdk.ts` script created with TypeScript and js-yaml dependency
2. Parser extracts `components.schemas` from OpenAPI YAML files
3. Generator maps OpenAPI types to TypeScript: string→string, integer→number, object→interface, array→T[], enum→union

5. Generates TypeScript interfaces with PascalCase naming from schema names
6. Includes JSDoc comments extracted from schema `description` fields
7. Outputs generated types to `src/types/<module>.types.ts`

### Architecture Overview

The SDK uses a **bespoke code generator** because Wildberries APIs have unique patterns:
- **Russian rate limit tables** in description fields (requires custom parsing)
- **Multi-domain URLs** per endpoint (not standard OpenAPI pattern)

- These tools generate generic types, but we need:
  - Rate limit extraction from description fields
  - Custom base URL detection from servers config
  - SDK-specific patterns (module structure, BaseClient delegation)
  - Full control over JSDoc generation and formatting

### Type Generation Architecture

**Component: Type Generator**

**Location:** `tools/generate-sdk.ts` and `tools/generators/`

**Purpose:** Transform OpenAPI 3.0.1 `components.schemas` into TypeScript interfaces

**Process Flow:**
```
1. Read OpenAPI YAML file (js-yaml)
2. Parse components.schemas section
3. For each schema:
   a. Extract schema name → convert to PascalCase
   b. Extract description → generate JSDoc
   c. Map OpenAPI type to TypeScript type
   d. Handle required/optional properties
   e. Resolve $ref references
   f. Generate interface declaration
4. Write all interfaces to src/types/<module>.types.ts
5. Format with Prettier
6. Validate with TypeScript compiler
```

**Output Example:**
```typescript
/**
 * Product card data model for Wildberries catalog
 * @see https://dev.wildberries.ru/...
 */
export interface ProductCard {
  id: number;
  brandName: string;
  title: string;
  description?: string;
  price: number;
  stock: number;
  images: string[];
  status: 'draft' | 'active' | 'archived';
}
```

### OpenAPI to TypeScript Type Mapping

**Type Mapping Rules:**

| OpenAPI Type | OpenAPI Format | TypeScript Type | Example |
|--------------|----------------|-----------------|---------|
| `string` | - | `string` | `name: string` |
| `string` | `date-time` | `string` | `createdAt: string` (ISO 8601) |
| `string` | `enum` | Union type | `status: 'new' \| 'confirmed'` |
| `integer` | `int32`, `int64` | `number` | `count: number` |
| `number` | `float`, `double` | `number` | `price: number` |
| `boolean` | - | `boolean` | `isActive: boolean` |
| `array` | - | `T[]` | `tags: string[]` |
| `object` | - | Interface | `metadata: Metadata` |
| `$ref` | - | Interface reference | `product: ProductCard` |
| No type specified | - | `unknown` | `data: unknown` |

**Special Cases:**

1. **Enums:** Generate TypeScript union types (not enum keyword)
   - OpenAPI: `enum: ['new', 'confirmed', 'shipped']`
   - TypeScript: `type OrderStatus = 'new' | 'confirmed' | 'shipped'`

2. **Optional Properties:** Determined by `required` array in schema
   - If property name NOT in `required` array → add `?` marker
   - Example: `description?: string`

3. **Nested Objects:** Generate inline interfaces or reference types
   - Simple nested object → inline type
   - Complex nested object → separate interface + $ref

4. **Arrays:** Recursively map item type
   - Array of primitives: `string[]`
   - Array of objects: `ProductCard[]`
   - Nested arrays: `string[][]`

5. **$ref Resolution:**
   - Parse `#/components/schemas/ProductCard`
   - Extract `ProductCard`
   - Convert to PascalCase if needed
   - Use as type reference

### Naming Conventions

**Interface Names: PascalCase from Schema Names**

| Schema Name (OpenAPI) | Interface Name (TypeScript) | Rationale |
|-----------------------|-----------------------------|-----------|
| `ProductCard` | `ProductCard` | Already PascalCase |
| `product_card` | `ProductCard` | Convert snake_case |
| `order-status` | `OrderStatus` | Convert kebab-case |
| `APIResponse` | `APIResponse` | Preserve existing PascalCase |

**Conversion Algorithm:**
```typescript
function toPascalCase(schemaName: string): string {
  return schemaName
    .split(/[-_]/)
    .map(word => word.charAt(0).toUpperCase() + word.slice(1).toLowerCase())
    .join('');
}
```

**File Naming: kebab-case**
- Output: `src/types/<module-name>.types.ts`
- Example: `src/types/general.types.ts`

**Property Names: Preserve Original**
- Keep property names exactly as in OpenAPI schema
- Usually camelCase: `brandName`, `createdAt`
- Do NOT transform property names

[Source: .claude/CLAUDE.md#Naming Conventions]

### Example: Type Generation from OpenAPI Schema

**Input: OpenAPI Schema (01-general.yaml)**
```yaml
components:
  schemas:
    PingResponse:
      type: object
      description: Health check response from API
      required:
        - status
        - timestamp
      properties:
        status:
          type: string
          description: API status
          enum: ['ok', 'error']
        timestamp:
          type: string
          format: date-time
          description: Server timestamp in ISO 8601 format
        message:
          type: string
          description: Optional status message
```

**Expected Output: TypeScript Interface (general.types.ts)**
```typescript
/**
 * Auto-generated TypeScript types for general module

 * DO NOT EDIT MANUALLY - Changes will be overwritten
 */

/**
 * Health check response from API
 */
export interface PingResponse {
  /**
   * API status
   */
  status: 'ok' | 'error';

  /**
   * Server timestamp in ISO 8601 format
   */
  timestamp: string;

  /**
   * Optional status message
   */
  message?: string;
}
```

- Schema name `PingResponse` → Interface `PingResponse` (already PascalCase)
- Required properties (`status`, `timestamp`) → no `?`
- Optional property (`message`) → `message?: string`
- Enum values → Union type `'ok' | 'error'`
- `date-time` format → `string` (not Date object - SDK returns raw API strings)
- JSDoc extracted from `description` fields

### Error Handling in Generator

**Graceful Degradation:**

1. **Missing YAML file:**
   - Log error: "File not found: {path}"
   - Exit with code 1
   - Do NOT generate partial output

2. **Invalid YAML syntax:**
   - Log error: "Invalid YAML: {error message}"
   - Exit with code 1

3. **Missing components.schemas:**
   - Log warning: "No schemas found in {file}"
   - Generate empty types file with comment explaining

4. **Unknown OpenAPI type:**
   - Map to `unknown`
   - Log warning: "Unknown type '{type}' in schema '{schemaName}'"
   - Continue generation

5. **Invalid $ref:**
   - Map to `unknown`
   - Log warning: "Unresolved $ref: {ref}"
   - Continue generation

**Logging:**
- Use console.log for success messages
- Use console.warn for warnings
- Use console.error for errors
- Include file name and schema name in all messages
