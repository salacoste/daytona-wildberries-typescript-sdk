## Story

**As a** marketplace seller,
**I want** to manage product questions and customer reviews,
**so that** I can engage with customers and improve product listings.

---

## Acceptance Criteria

1. Communications module extended from Story 3.5 with Q&A and Reviews functionality
2. `getQuestions(filters: QuestionFilters)` method retrieves unanswered and answered product questions
3. `answerQuestion(questionId: string, answer: string)` method provides answer to customer question
4. `getReviews(filters: ReviewFilters)` method retrieves product reviews with ratings
5. `respondToReview(reviewId: string, response: string)` method adds seller response to review
6. Question and review filters support product ID (nmId), answered status, date range, pagination (take/skip)
7. Reviews include rating (1-5 stars), text, customer info, photos, video support
8. Rate limits enforced per endpoint (3 requests/second, burst 6)
9. Unit tests validate Q&A and review methods
10. Integration tests validate question answering and review response workflows
11. Example code demonstrates managing product Q&A and responding to reviews

### OpenAPI Source

- **Source File**: `wildberries_api_doc/09-communications.yaml`
- **Base URL**: `https://feedbacks-api.wildberries.ru` (Feedbacks API domain)
- **Questions Endpoints**:
  - `GET /api/v1/questions` - List questions with filters
  - `PATCH /api/v1/questions` - Answer, reject, or mark as viewed
- **Reviews Endpoints**:
  - `GET /api/v1/feedbacks` - List reviews with filters
  - `POST /api/v1/feedbacks/answer` - Respond to review
  - `PATCH /api/v1/feedbacks/answer` - Edit response to review
- **Authentication**: Header-based API Key (`Authorization: Bearer <key>`)
- **Rate Limits**: 3 requests/second, interval 333ms, burst 6 requests

### Module Architecture

**Traditional REST Pattern** (Unlike Story 3.5's event-based architecture):
- Standard GET endpoints for listing with query parameters
- PATCH/POST endpoints for updates
- Simple pagination with take/skip parameters
- Product filtering via nmId parameter

**Questions Management**:
- `GET /api/v1/questions?isAnswered={bool}&take={n}&skip={n}` - List questions
- Required params: isAnswered, take, skip
- Optional params: nmId (product filter), order (dateAsc/dateDesc), dateFrom, dateTo
- Max limits: take + skip <= 10000, max 10000 questions per response
- Question states: 'none' (rejected), 'wbRu' (answered/visible), 'suppliersPortalSynch' (new)

**PATCH /api/v1/questions** - Multi-purpose endpoint with oneOf schemas:
1. **Mark as viewed**: `{ id, wasViewed: true }`
2. **Answer/reject**: `{ id, answer: { text }, state: 'wbRu'|'none' }`
   - state='wbRu': Answer visible to customers
   - state='none': Reject question (not visible to customers)

**Reviews Management**:
- `GET /api/v1/feedbacks?isAnswered={bool}&take={n}&skip={n}` - List reviews
- Required params: isAnswered, take, skip
- Optional params: nmId, order, dateFrom, dateTo
- Max limits: take max 5000, skip max 199990
- Review structure:
  - productValuation: Rating 1-5 stars
  - text, pros, cons: Review content
  - photoLinks[]: Array of {fullSize, miniSize} URLs
  - video: {previewImage, link (HLS .m3u8), durationSec}
  - userName: Customer name
  - matchingSize: 'ok', 'smaller', 'bigger'
  - bables[]: Customer tags

**POST /api/v1/feedbacks/answer** - Respond to review:
- Request: `{ id, text }` (text: min 2, max 5000 chars)
- Response: 204 No Content
- Note: Review ID not validated by API

**PATCH /api/v1/feedbacks/answer** - Edit response:
- Request: `{ id, text }` (text: min 2, max 5000 chars)
- Response: 204 No Content
- Limitation: Can only edit once within 60 days
- Check answer.editable field in Review before attempting edit

### Q&A Management Patterns

**Typical Question Management Workflow**:
1. Fetch unanswered questions with `getQuestions({ isAnswered: false, take: 20, skip: 0 })`
2. For each question:
   - Review question text and product details
   - Decide to answer or reject
   - Call `answerQuestion(questionId, answerText, reject)` with appropriate state
3. Optionally mark questions as viewed without answering: `markQuestionViewed(questionId)`
4. Paginate through questions if count > 20 (adjust skip parameter)

**Question States**:
- **'suppliersPortalSynch'**: New question from customer
- **'wbRu'**: Answered question visible to all customers
- **'none'**: Rejected question (not visible to customers)

**Answer Editing**:
- Questions can be edited once within 60 days
- Check answer.editable field in Question object
- Use same `answerQuestion()` method with updated text
- PATCH endpoint handles both initial answer and edit

### Review Management Patterns

**Typical Review Management Workflow**:
1. Fetch unanswered reviews with `getReviews({ isAnswered: false, take: 20, skip: 0 })`
2. For each review:
   - Read rating (productValuation 1-5)
   - Read review text, pros, cons
   - View photos (photoLinks[])
   - View video if present (HLS playlist)
   - Analyze customer sentiment
3. Respond professionally with `respondToReview(reviewId, responseText)`
4. If response needs editing: `editReviewResponse(reviewId, newResponseText)`

**Review Response Best Practices**:
- Respond within 24-48 hours for better customer engagement
- Professional tone: Thank customer, address concerns, offer solutions
- Length: 2-5000 characters (validate before sending)
- Editing: Can edit once within 60 days - check answer.editable field
- Negative reviews: Address issues constructively, offer to resolve offline

**Photo and Video Handling**:
- **Photos**: photoLinks[] array with fullSize and miniSize URLs
- **Video**: HLS playlist format (index.m3u8), includes preview image and duration
- Display photos/videos in UI to understand customer context
- Use photo/video evidence when addressing product quality concerns

**Filtering Strategies**:
- **By Product**: Use nmId to filter questions/reviews for specific product
- **By Status**: isAnswered=false for unanswered, true for answered
- **By Date**: dateFrom/dateTo for time-based analysis
- **Pagination**: Start with take=20, adjust based on volume

### Validation Rules

**Question Validation**:
- questionId: Non-empty string
- answerText: Non-empty string
- state: 'wbRu' (answer) or 'none' (reject)

**Review Validation**:
- reviewId: Non-empty string
- responseText: Length 2-5000 characters
- Note: API doesn't validate IDs - invalid IDs won't throw errors

**Pagination Validation**:
- Questions: take + skip <= 10000, max 10000 questions per response
- Reviews: take max 5000, skip max 199990
- Both: take and skip are required parameters
